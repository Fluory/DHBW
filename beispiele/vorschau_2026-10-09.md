### Rückblick: Termin 1 (05.10.) – Einführung, Algorithmen, erstes Python
*Es ging darum, was ein Algorithmus ist, wie Code auf dem Rechner ausgeführt wird und wie du Python mit `uv`, `ruff` und `ty` startklar machst.*

#### Algorithmen
**Was ist das?** Ein Algorithmus ist eine Schrittfolge, die ein Problem systematisch löst, unabhängig von der Programmiersprache. Ein Kochrezept ist ein Algorithmus. Ein BWL-Beispiel: Wenn der Lagerbestand unter den Meldebestand fällt, wird automatisch nachbestellt.

**Das Wichtigste:**

- Anforderungen: Endlichkeit, Ausführbarkeit, Korrektheit, Effizienz.
- **Terminierend:** Der Algorithmus endet bei jeder erlaubten Eingabe.
- **Determiniert:** Gleiche Eingabe führt immer zum gleichen Ergebnis.
- **Deterministisch:** Der nächste Schritt ist zu jedem Zeitpunkt eindeutig.

**Achtung:** Determiniert und deterministisch sind nicht dasselbe. Ein Algorithmus kann determiniert sein (immer dasselbe Ergebnis), obwohl er unterwegs zwischen gleichwertigen Wegen wählt, also nicht deterministisch ist. Das ist eine typische Klausurfrage.

#### Datenstrukturen
**Was ist das?** Eine Datenstruktur legt fest, wie Daten geordnet sind, damit man schnell an sie herankommt. Ein **Stack** funktioniert wie ein Tellerstapel: Was zuletzt draufkam, nimmst du zuerst (LIFO, z. B. die Zurück-Taste im Browser). Eine **Queue** funktioniert wie eine Warteschlange (FIFO, z. B. Druckaufträge).

**Das Wichtigste:**

- Array (Index, feste Größe), Liste (flexibel), Baum (Hierarchien), Graph (Netze, Routen).
- In Python eingebaut: `list`, `tuple`, `dict`, `set`.

**Achtung:** LIFO gehört zum Stack, FIFO zur Queue. Wer das verwechselt, verliert leichte Punkte.

#### Wie Code ausgeführt wird
**Was ist das?** Ein Rechner versteht nur Maschinencode. Ein **Compiler** übersetzt das ganze Programm vorab (C, Rust). Ein **Interpreter** führt Anweisung für Anweisung aus. Python liegt dazwischen: CPython übersetzt in **Bytecode**, und die Python-VM führt ihn aus. Java und C# machen es ähnlich.

**Das Wichtigste:**

- Kompiliert ist schnell, läuft aber nur auf der Zielplattform. Interpretiert lässt sich schnell ausprobieren, läuft aber langsamer.
- Bytecode + VM ist portabel. Ein JIT kompiliert häufig genutzten Code zur Laufzeit.
- Python ist **dynamisch, aber stark typisiert**: Werte haben Typen, Variablen nicht.

**Achtung:** „Python ist interpretiert“ stimmt nur halb. Die vollständige Antwort lautet: Bytecode plus VM.

#### Erstes Python und Werkzeuge
**Was ist das?** Blöcke entstehen durch Einrückung (4 Leerzeichen) statt durch `{}`, und ein `:` öffnet einen Block.

```bash
uv run hallo.py          # Programm ausführen
uv run ruff check .      # Stil prüfen
uv run ty check          # Typen prüfen
```

**Das Wichtigste:**

- Im Kurs schreibst du Code im Texteditor, ohne IDE und ohne KI. Fehlermeldungen selbst zu lesen ist das Ziel.
- Typangaben schreibst du überall, `ty` prüft sie.

**Achtung:** Groß- und Kleinschreibung zählt: `Print` ist nicht `print`.

#### Kommentare und Docstrings
**Was ist das?** Python ignoriert Kommentare, sie richten sich an Menschen. `#` kommentiert bis zum Zeilenende. Ein Docstring `"""…"""` beschreibt eine Funktion.

```python
# Rabatt erst ab 10 Stück, siehe AGB § 4
def kreisflaeche(radius: float) -> float:
    """Berechnet die Fläche eines Kreises.

    Args:
        radius: Radius in Metern, nicht negativ.

    Returns:
        Die Fläche in Quadratmetern.
    """
    return 3.14159 * radius**2
```

**Das Wichtigste:**

- Ein Kommentar erklärt das **Warum**, nicht das Was. `# Setze netto auf 100` ist überflüssig.
- Docstrings schreibst du im **Google-Stil** mit `Args:` und `Returns:`.

**Achtung:** Einen Blockkommentar wie `/* … */` gibt es in Python nicht.

#### Einfache Datentypen
**Was ist das?** Der Datentyp legt fest, welche Art von Wert vorliegt und was du damit tun darfst. `type(42)` ergibt `<class 'int'>`.

**Das Wichtigste:**

- `int`: ganze Zahlen, beliebig groß (`2 ** 100` funktioniert), `1_000_000` ist lesbar.
- `float`: Kommazahlen mit Dezimal**punkt**. `0.1 + 0.2 == 0.3` ist `False`.
- `bool`: `True` und `False`, großgeschrieben.
- `str`: Text, unveränderlich. Ein einzelnes Zeichen ist ein `str` der Länge 1, `ord("A")` ergibt 65, `chr(66)` ergibt `"B"`.
- `None`: „kein Wert“. Das ist nicht 0 und nicht `""`. Mit `telefon: str | None = None`.

**Achtung:** Postleitzahlen und Telefonnummern speicherst du als `str`, weil man damit nicht rechnet und führende Nullen sonst verloren gehen. Für Geld ist `float` ungeeignet, dafür gibt es `Decimal("19.99")`.

#### Variablen und Konstanten
**Was ist das?** Eine Variable ist ein **Namensschild** an einem Wert, keine Box. `=` bedeutet „zeigt ab jetzt auf“, nicht „ist gleich“.

```python
alter: int = 25
zahl = 15
zahl = zahl + 1        # erst rechts rechnen, dann zuweisen → 16
a, b = 1, 2
a, b = b, a            # tauschen ohne Hilfsvariable
from typing import Final
MWST_SATZ: Final = 0.19
```

**Das Wichtigste:**

- Der Typ gehört zum Wert. Die Typangabe ist ein Versprechen, das `ty` prüft.
- Schreibweisen: Variablen und Funktionen in `snake_case`, Konstanten in `UPPER_SNAKE_CASE`, Klassen in `PascalCase`. Keine Umlaute im Code: `groesse`.
- Eine Variable aus einem `if`-Block lebt danach weiter. Erst Funktionen schaffen einen eigenen Gültigkeitsbereich.

**Achtung:** `wert = 3,5` ist kein Fehler, sondern das Tupel `(3, 5)`. `anzahl: int` allein erzeugt keine Variable, ein späteres `print(anzahl)` gibt einen NameError. Auch `Zahl` und `zahl` sind zwei verschiedene Namen.

#### Operatoren
**Was ist das?** Mit Operatoren rechnest, vergleichst und verknüpfst du Werte.

```python
print(7 / 2, 7 // 2, 7 % 2, -7 // 2)   # 3.5 3 1 -4
summe = 0
summe += 5                              # 5
print(18 <= 30 <= 65)                   # True – verketteter Vergleich
print(True and False, not True)         # False False
```

**Das Wichtigste:**

- `/` liefert **immer** `float` (`6 / 3` ergibt `2.0`). `//` rundet **ab** zur kleineren Zahl, `%` gibt den Rest.
- Logische Operatoren sind Wörter: `and`, `or`, `not` statt `&&`, `||`, `!`.
- `==` vergleicht den Inhalt, auch bei Strings. `is` verwendest du nur bei `None`.

**Achtung:** `-7 // 2` ergibt `-4` (in Java `-3`). `x++` ist ein SyntaxError, `++x` ist gültig, tut aber nichts. `alter == "30"` ist `False`, weil die Zahl 30 nicht der Text "30" ist.

#### Strings, f-Strings und Typumwandlung
**Was ist das?** Strings kannst du verketten (`+`), wiederholen (`*`) und ausschneiden. Positionen zählen ab 0, negative von hinten. Ein f-String setzt Werte direkt ein.

```python
"Hallo"[1:3]                 # "al"
f"Preis: {3.5:.2f} €"        # "Preis: 3.50 €"
int(9.99)                    # 9 – schneidet ab!
"Alter: " + 36               # TypeError
"Alter: " + str(36)          # ok
```

**Das Wichtigste:**

- Python wandelt nur zwischen Zahlen automatisch um (bool → int → float), **nie** zwischen Text und Zahl. Das ist mit „stark typisiert“ gemeint.
- `int()` schneidet ab, `round()` rundet. `round(9.5)` ergibt 10, aber `round(2.675, 2)` ergibt wegen float 2.67.

**Achtung:** `int(19.99 * 100)` ergibt 1998, ein Cent ist weg. Abhilfe: `round()` oder `Decimal`.

#### Syntax vs. Semantik und Fehlermeldungen
**Was ist das?** Die **Syntax** ist die Grammatik, also die Form des Codes. Die **Semantik** ist die Bedeutung, also was der Code tut. Ein Syntaxfehler fällt vor dem Start auf. Ein Logikfehler fällt nie automatisch auf.

**Das Wichtigste:**

- Fehlerarten: Syntaxfehler (vor dem Start), Typfehler (fängt `ty` vorher ab), Laufzeitfehler (z. B. `ZeroDivisionError`), Logikfehler (findest du nur durch Testen).
- Tracebacks liest du **von unten nach oben**: In der letzten Zeile steht, was passiert ist, darüber steht, wo.

**Achtung:** `5 + 2 / 2` ergibt 6.0 und nicht 3.5, weil Punkt vor Strich gilt. Das ist ein typischer Semantikfehler aus den Übungen.

#### Daten, Information, Informationstheorie
**Was ist das?** **Daten** sind Rohwerte ohne Bedeutung, etwa `000000111` = 7. Mit **Kontext** werden sie zur **Information** („Es ist 7 °C in Deutschland“), daraus entsteht **Wissen** („Es ist kalt“) und schließlich eine **Handlung** („Ich ziehe eine Jacke an“). Dieselbe 7 bedeutet in Fahrenheit etwas völlig anderes, nämlich etwa −13 °C. Shannon (1948) hat eine Theorie aufgestellt, wie viel Information in einer Nachricht steckt, unabhängig von ihrer Bedeutung.

**Das Wichtigste:**

- Das Bit ist die Grundeinheit. Die Entropie misst den durchschnittlichen Informationsgehalt einer Quelle.
- **Redundanz entfernen** heißt Kompression, z. B. RLE (`AAAABBBCC` → `4A3B2C`) oder Huffman (häufige Zeichen bekommen kurze Codes).
- **Redundanz hinzufügen** heißt Fehlererkennung und -korrektur (Paritätsbit, Hamming-Code), kostet aber Datenrate.
- Die Kanalkapazität (Shannon-Grenze) ist die maximale Datenrate eines gestörten Kanals.

**Achtung:** Kompression und Fehlerkorrektur arbeiten mit Redundanz in **entgegengesetzte** Richtungen.

#### Digitalisierung und ihr Nutzen
**Was ist das?** Technisch heißt Digitalisierung, analoge in diskrete, meist binäre Werte zu überführen. Betriebswirtschaftlich heißt es, mit Daten und Algorithmen Prozesse, Produkte und Geschäftsmodelle neu oder besser zu machen. Beispiel: Uber ist ein Taxiunternehmen ohne eigene Autos.

**Das Wichtigste:**

- Drei Nutzenstufen: **Automatisierung** (Abläufe in IT gießen), **Informatisierung** (die anfallenden Daten für Entscheidungen nutzen, BI) und **Transformation** (ganz neue Prozesse, Business Process Reengineering).
- Früher war IT eine „EDV-Abteilung“ ohne strategische Rolle (Carr 2003: *IT doesn't matter*). Seit dem Internet gehört IT zum Kerngeschäft.
- Ökonomische Effekte: andere Fix- und variable Kosten, Netzwerkeffekte, Long Tail, Freemium, niedrigere Eintrittsbarrieren, Branchen wachsen zusammen.

**Achtung:** Die **vier Phasen der Digitalisierung** (wirtschaftliche Sicht, von einzelnen Funktionen bis zur überbetrieblichen m:n-Integration) sind nicht dasselbe wie die **fünf Epochen** der IT-Infrastruktur (technische Sicht).

#### Fünf Epochen der IT-Infrastruktur
**Was ist das?** Die IT in Unternehmen ist in mehr als 65 Jahren gewachsen. Jede Epoche bringt eine Technik dazu, die alten bleiben parallel bestehen (deshalb immer „bis heute“).

**Das Wichtigste:**

1. **Groß- und Minirechner** (ab 1959): IBM 1401 mit Terminals, alles von einem Hersteller. DEC-Minicomputer machten die EDV dezentraler.
2. **Personal Computing** (ab 1981): IBM-PC, „Wintel“, Tabellenkalkulation. Vernetzt erst ab etwa 1990.
3. **Client-Server** (ab 1983): Clients für die Eingabe, Server für Daten und Logik, oft mehrschichtig (N-Tier). Beispiel SAP R/3 mit separatem Datenbankserver.
4. **Betriebliche und internetbasierte Informationssysteme** (ab 1992): Ab 1995 verbindet TCP/IP heterogene Netze, auch mit Kunden und Lieferanten.
5. **Cloud Computing** (ab 2000): IaaS, PaaS und SaaS als Abo über den Browser. AWS seit 2002, Hyperscaler wie Azure, GCP oder STACKIT (Schwarz-Gruppe).

**Achtung:** Epochen lösen sich nicht ab, sie überlagern sich. Cloud wird im 2. Semester vertieft.

#### Treiber des technischen Fortschritts
**Was ist das?** Die Epochen wurden möglich, weil Rechenleistung exponentiell stieg und die Kosten exponentiell fielen.

**Das Wichtigste:**

- **Moore (1965):** Die Zahl der Transistoren pro Chip verdoppelt sich, zuerst jährlich, später alle zwei Jahre. Die geläufige Fassung „Leistung verdoppelt sich alle 18 Monate“ stammt **nicht** von Moore selbst. Heute steigen die Kosten pro Transistor wieder, Wachstum kommt über GPU-Cluster (Nvidia Blackwell: 208 Mrd. Transistoren).
- **Massenspeicher:** Die Kapazität wächst exponentiell, der Preis fällt drastisch.
- **Metcalfe:** n Teilnehmer haben n·(n−1) mögliche Verbindungen, der Nutzen eines Netzes wächst also überproportional (soziale Netzwerke).
- **Kommunikationskosten** gehen gegen 0. Mehr als 5 Mrd. Menschen sind online, die IPv4-Adressen sind aufgebraucht.
- **Standards** (ASCII, Ethernet, TCP/IP, HTML) bringen Skaleneffekte und sinkende Preise.

**Achtung:** Bei Metcalfe ist n·(n−1) mathematisch **quadratisch**, auf den Folien steht trotzdem „exponentiell“. In der Klausur nennst du die Formel.

#### Datentypen und Datenstrukturen
**Was ist das?** Dasselbe Bitmuster kann eine Zahl, ein Zeichen oder eine Farbe sein. Erst der **Datentyp** legt fest, wie es gelesen wird und welche Operationen erlaubt sind (vgl. Daten → Information aus VL01). Eine **Datenstruktur** ordnet viele Werte, etwa als Array, Liste, Stack, Queue oder Baum.

**Das Wichtigste:**

- Bei einfachen Typen (Ganzzahl, Gleitkommazahl, Wahrheitswert, Zeichen) bestimmt der Typ auch den Speicherbedarf und den Wertebereich, z. B. 8 Bit = 256 Werte.
- Das überschneidet sich stark mit Programmierung VL 1–2, nur dass GIT aus Hardware-Sicht draufschaut.

**Achtung:** In Python sind `int` unbegrenzt. In anderen Sprachen und auf Hardware-Ebene haben Ganzzahlen eine feste Breite und können **überlaufen**.

#### Programmiersprachen und Variablen
**Was ist das?** Hier geht es vermutlich um einen Überblick über Sprachfamilien und Paradigmen sowie darum, was eine Variable technisch ist: ein Name für einen Speicherplatz bzw. Wert. Die Agenda von VL01 nennt „Vielfalt und unerwartete Besonderheiten einiger Programmiersprachen“.

**Das Wichtigste:**

- Compiler, Interpreter und Bytecode kennst du schon aus Programmierung VL 1.

**Achtung:** Das ist kein Programmierkurs. Es geht eher ums Einordnen als ums Schreiben von Code.

#### Logische und arithmetische Operationen
**Was ist das?** Rechner arbeiten letztlich mit UND, ODER und NICHT auf Bits. Daraus lassen sich auch Addierer bauen. Beispiel: `1 UND 0 = 0`, `1 ODER 0 = 1`.

**Das Wichtigste:**

- Wahrheitstabellen für AND, OR, NOT, voraussichtlich auch XOR.

**Achtung:** Kommt vielleicht erst am 14.10.

#### Zahlensysteme und Kodierungen
**Was ist das?** Dieselbe Zahl lässt sich in verschiedenen Basen schreiben: dezimal 13 = binär `1101` = hexadezimal `D`. Kodierungen wie ASCII oder Unicode ordnen Zeichen Zahlen zu, `"A"` ist 65 (siehe `ord("A")` aus Programmierung VL 2).

**Das Wichtigste:**

- Binär → dezimal: Stellenwerte addieren, `1101` = 8 + 4 + 0 + 1 = 13.
- Hex fasst 4 Bit zu einer Ziffer zusammen (0–9, A–F).

**Achtung:** Kommt vielleicht erst am 14.10. Umrechnen ist ein Klassiker in der Klausur, also üben.
