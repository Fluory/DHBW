### Rückblick: Termin 1 (05.10.) – Einführung, Algorithmen, erstes Python

Im ersten Termin ging es um die Frage, was Programmieren eigentlich ist, bevor überhaupt Code geschrieben wurde. Der Weg führte vom Algorithmus als Idee über die Frage, wie ein Rechner Code ausführt, bis zum ersten eigenen Python-Programm. Am Ende stand die Werkzeugkette, mit der du das ganze Semester arbeitest.

#### Algorithmen

**Was ist das?** Ein Algorithmus ist eine genaue Schrittfolge, die ein Problem systematisch löst. Er ist unabhängig davon, in welcher Sprache man ihn später aufschreibt: Dasselbe Verfahren kann in Python, Java oder als Text auf Papier stehen. Ein Kochrezept ist ein Algorithmus, und ein typisches BWL-Beispiel ist die automatische Nachbestellung. Fällt der Lagerbestand unter den Meldebestand, wird eine Bestellung ausgelöst, sonst passiert nichts. Weitere Beispiele aus der Vorlesung waren Kredit-Scoring, Warenkorbempfehlungen und Schichtplanung. Überall dort steckt eine feste Regel dahinter, die ein Rechner ohne Nachfragen abarbeiten kann.

**Das Wichtigste:** Ein Algorithmus muss vier Anforderungen erfüllen. Er muss endlich beschreibbar sein, jeder Schritt muss ausführbar sein, er muss das richtige Ergebnis liefern (korrekt) und er soll das mit vertretbarem Aufwand tun (effizient). Dazu kommen drei Eigenschaften, die gern abgefragt werden. **Terminierend** heißt, dass der Algorithmus bei jeder erlaubten Eingabe irgendwann endet. **Determiniert** heißt, dass dieselbe Eingabe immer zum selben Ergebnis führt. **Deterministisch** heißt, dass zu jedem Zeitpunkt eindeutig feststeht, welcher Schritt als Nächstes kommt.

**Achtung:** Determiniert und deterministisch klingen fast gleich, meinen aber Verschiedenes. Das eine betrifft das *Ergebnis*, das andere den *Weg*. Ein Algorithmus kann unterwegs zufällig zwischen zwei gleichwertigen Wegen wählen, also nicht deterministisch sein, und trotzdem immer dasselbe Ergebnis liefern, also determiniert sein. Genau diese Unterscheidung ist eine typische Klausurfrage.

#### Datenstrukturen

**Was ist das?** Ein Algorithmus arbeitet auf Daten, und wie diese Daten geordnet sind, entscheidet darüber, wie schnell er an sie herankommt. Diese Ordnung nennt man Datenstruktur. Ein **Stack** funktioniert wie ein Tellerstapel: Was zuletzt draufgelegt wurde, nimmst du zuerst wieder herunter (LIFO, *last in, first out*). Die Zurück-Taste im Browser arbeitet so, denn sie springt zur zuletzt besuchten Seite. Eine **Queue** funktioniert wie die Schlange an der Kasse: Wer zuerst kommt, ist zuerst dran (FIFO, *first in, first out*). So werden zum Beispiel Druckaufträge abgearbeitet.

**Das Wichtigste:** Neben Stack und Queue gab es vier weitere Grundformen. Ein Array greift über einen Index zu und hat eine feste Größe, eine Liste kann wachsen und schrumpfen. Ein Baum bildet Hierarchien ab, zum Beispiel ein Organigramm oder Ordner auf der Festplatte. Ein Graph bildet Netze ab, zum Beispiel Straßen oder Lieferbeziehungen. Python bringt mit `list`, `tuple`, `dict` und `set` schon die wichtigsten Sammlungen mit, die du in späteren Vorlesungen genauer kennenlernst.

**Achtung:** LIFO gehört zum Stack, FIFO zur Queue. Wer das verwechselt, verschenkt leichte Punkte. Merk dir einfach den Tellerstapel.

#### Wie Code ausgeführt wird

**Was ist das?** Ein Prozessor versteht nur Maschinencode, also Folgen aus Nullen und Einsen. Alles, was du in einer höheren Sprache schreibst, muss deshalb übersetzt werden. Dafür gibt es drei Strategien. Ein **Compiler** übersetzt das ganze Programm vorab in Maschinencode, wie bei C oder Rust. Das Ergebnis läuft schnell, aber nur auf der Plattform, für die übersetzt wurde. Ein **Interpreter** liest das Programm Anweisung für Anweisung und führt jede direkt aus. Das ist bequem zum Ausprobieren, aber langsamer. Der dritte Weg liegt dazwischen: Der Code wird in einen plattformunabhängigen **Bytecode** übersetzt, und eine virtuelle Maschine (VM) führt diesen aus. Java, C# und auch Python arbeiten so. Bei Python übersetzt CPython deinen Code in Bytecode, den die Python-VM ausführt. Häufig genutzte Teile kann ein **JIT-Compiler** zur Laufzeit zusätzlich in Maschinencode übersetzen, seit Python 3.13 gibt es das experimentell.

**Das Wichtigste:** Heute ordnet man Sprachen weniger nach Generationen ein als nach Paradigmen: imperativ, objektorientiert, funktional, deklarativ. Python ist multiparadigmatisch, beherrscht also mehrere davon. Außerdem ist Python **dynamisch, aber stark typisiert**. Dynamisch heißt, dass eine Variable nacheinander auf Werte verschiedenen Typs zeigen darf. Stark heißt, dass Python Typen nicht stillschweigend vermischt.

**Achtung:** Die Antwort „Python ist interpretiert“ ist nur halb richtig. Vollständig lautet sie: Python wird in Bytecode übersetzt, den eine VM ausführt.

#### Erstes Python und Werkzeuge

**Was ist das?** Das erste Programm war `print("Hello World!")`. Wichtiger als die Zeile selbst ist, wie Python Code gliedert. Statt geschweifter Klammern bilden Einrückungen von vier Leerzeichen die Blöcke, ein Doppelpunkt öffnet einen Block, und Semikolons am Zeilenende gibt es nicht. Damit du sauber arbeitest, nutzt der Kurs drei Werkzeuge. **uv** installiert Python und verwaltet dein Projekt, **ruff** prüft und formatiert den Stil, **ty** prüft die Typangaben, bevor das Programm überhaupt läuft.

```bash
uv run hallo.py          # Programm ausführen
uv run ruff check .      # Stil prüfen
uv run ty check          # Typen prüfen
```

**Das Wichtigste:** Im Kurs schreibst du Code im einfachen Texteditor, ohne IDE und ohne KI. Der Dozent begründet das damit, dass du Fehlermeldungen selbst lesen können sollst, und das hält er für die wichtigste Fähigkeit überhaupt. Außerdem schreibst du in jedem Programm Typangaben dazu, auch wenn Python sie selbst nicht verlangt.

**Achtung:** Python unterscheidet Groß- und Kleinschreibung. `Print` ist nicht `print`, und `Zahl` ist eine andere Variable als `zahl`.

**Hausaufgabe:** `uv`, Python 3.14 und einen Editor installieren, `hallo.py` um drei Zeilen erweitern (Name, Unternehmen, Lieblingsort) und w3schools Python von HOME bis Comments durcharbeiten. VL 2 beginnt laut Folien direkt mit der Frage, ob „Hello World“ bei allen geklappt hat.

Heute geht es um die Bausteine, aus denen jedes Programm besteht. Der Bogen ist logisch aufgebaut: Erst klärt die Vorlesung, welche Arten von Werten es gibt (Datentypen). Dann geht es darum, wie man diesen Werten Namen gibt (Variablen), und dann, wie man mit ihnen rechnet und sie vergleicht (Operatoren). #### Kommentare und Docstrings

**Was ist das?** Die Vorlesung steigt mit einer Wiederholung ein. Ein Kommentar ist Text im Programm, den Python ignoriert. Er richtet sich an Menschen, an dich selbst in drei Wochen oder an Kolleginnen und Kollegen. Alles ab `#` bis zum Zeilenende ist Kommentar. Für Funktionen gibt es zusätzlich den **Docstring** in dreifachen Anführungszeichen. Werkzeuge können daraus automatisch eine Dokumentation erzeugen.

```python
# Rabatt erst ab 10 Stück, siehe AGB § 4
def kreisflaeche(radius: float) -> float:
    """Berechnet die Fläche eines Kreises.

    Args:
        radius: Radius in Metern, nicht negativ.

    Returns:
        Die Fläche in Quadratmetern.
    """
    return 3.14159 * radius**2
```

**Das Wichtigste:** Ein guter Kommentar erklärt das *Warum*, denn das *Was* soll der Code selbst zeigen. „Rabatt erst ab 10 Stück, siehe AGB § 4“ ist hilfreich, weil es eine Information enthält, die im Code nicht steht. „Setze netto auf 100“ über `netto = 100.0` ist überflüssig. Docstrings schreibst du im **Google-Stil**: erst ein kurzer Satz, dann `Args:` für die Parameter und `Returns:` für das Ergebnis. Ausführlich kommt das in VL 4.

**Achtung:** Einen Blockkommentar wie `/* … */` aus Java gibt es in Python nicht. Mehrzeilige Kommentare bestehen einfach aus mehreren Zeilen mit `#`.

#### Einfache Datentypen

**Was ist das?** Ein Datentyp beschreibt, welche Art von Wert vorliegt, und legt damit fest, was du mit ihm tun darfst. Zahlen kannst du teilen, Texte nicht. Die Vorlesung verknüpft das mit der DIKW-Pyramide (Daten, Information, Wissen, Weisheit): Programme arbeiten auf der untersten Stufe, mit Daten wie `42000` und `"Juli"`. Erst der Datentyp sagt, was diese Daten sind. In Python hat jeder Wert einen Typ, und `type(42)` zeigt ihn an: `<class 'int'>`. Anders als in Java gibt es keine Trennung zwischen „primitiven“ Typen und Objekten, jeder Wert ist ein Objekt.

**Das Wichtigste:** Heute kommen die fünf einfachen Typen dran.

- **`int`** für ganze Zahlen. Es gibt nur diesen einen Typ statt `byte`, `short`, `int` und `long` wie in Java, und er ist beliebig groß. `2 ** 100` funktioniert ohne Überlauf, und `83_500_000` darfst du mit Unterstrichen lesbar schreiben.
- **`float`** für Kommazahlen, mit Dezimal*punkt*. Intern werden sie binär gespeichert, deshalb sind manche Dezimalzahlen nur Näherungen: `0.1 + 0.2` ergibt `0.30000000000000004`.
- **`bool`** mit genau zwei Werten, `True` und `False`. Sie entstehen bei Vergleichen und steuern ab VL 3 Entscheidungen.
- **`str`** für Text. Einen eigenen Zeichentyp wie `char` gibt es nicht, ein Zeichen ist ein String der Länge 1. Intern ist jedes Zeichen eine Unicode-Zahl: `ord("A")` ergibt 65, `chr(66)` ergibt `"B"`.
- **`None`** für „kein Wert vorhanden“, zum Beispiel für eine noch unbekannte Telefonnummer: `telefon: str | None = None`.

**Achtung:** Postleitzahlen und Telefonnummern speicherst du als `str`, nicht als `int`. Mit ihnen rechnet man nicht, und eine führende Null würde sonst verschwinden. Für Geldbeträge ist `float` wegen der Rundungsfehler ungeeignet, dafür gibt es `Decimal`. `None` ist weder 0 noch der leere String.

#### Variablen und Konstanten

**Was ist das?** Eine Variable ist ein Name, der auf einen Wert zeigt. Der Dozent nutzt dafür das Bild vom **Namensschild**, das an einem Wert hängt, im Gegensatz zu Java, wo eine Variable eher eine Box mit fester Form ist. Daraus folgt der wichtigste Gedanke der Vorlesung: Der Typ gehört zum Wert, nicht zum Namen. Eine Variable entsteht, sobald du ihr zum ersten Mal etwas zuweist, eine eigene Deklaration gibt es nicht. Das Gleichheitszeichen bedeutet dabei „zeigt ab jetzt auf“ und nicht „ist gleich“ wie in der Mathematik. Deshalb ist `zahl = zahl + 1` sinnvoll: Erst rechnet Python rechts das Ergebnis aus, dann hängt es das Schild `zahl` an den neuen Wert.

```python
alter: int = 25
zahl = 15
zahl = zahl + 1        # 16
a, b = 1, 2
a, b = b, a            # Werte tauschen ohne Hilfsvariable
from typing import Final
MWST_SATZ: Final = 0.19
```

**Das Wichtigste:** Mit `alter: int = 25` schreibst du eine **Typangabe** dazu. Python selbst ignoriert sie beim Ausführen, aber `ty` prüft sie vorher. Sie ist ein Versprechen, auf dessen Einhaltung `ty` achtet: Weist du später `alter = "fünfundzwanzig"` zu, meldet `ty` einen Fehler. Konstanten gibt es in Python eigentlich nicht. Die Konvention ist, sie in Großbuchstaben zu schreiben, und mit `Final` kann `ty` prüfen, dass niemand sie überschreibt. Sinnvoll sind Konstanten, weil `netto * MWST_SATZ` mehr sagt als `netto * 0.19` und eine Änderung nur an einer Stelle nötig ist. Für Namen gelten feste Schreibweisen: Variablen und Funktionen in `snake_case`, Konstanten in `UPPER_SNAKE_CASE`, Klassen in `PascalCase`. Umlaute lässt du weg, also `groesse` statt `größe`.

**Achtung:** Hier liegen mehrere Klausurfallen. `wert = 3,5` ist kein Fehler, sondern erzeugt das Tupel `(3, 5)`, denn das Komma trennt Werte. `anzahl: int` allein erzeugt keine Variable, ein späteres `print(anzahl)` bricht mit einem `NameError` ab. Und eine Variable, die in einem `if`-Block entsteht, lebt danach weiter. Wurde der Block aber nicht ausgeführt, existiert sie gar nicht, und der nächste Zugriff scheitert.

#### Operatoren

**Was ist das?** Operatoren sind Zeichen oder Wörter, mit denen Python Werte verknüpft. Es gibt fünf Gruppen: arithmetische Operatoren zum Rechnen, Zuweisungsoperatoren wie `+=` zum Rechnen und Speichern in einem Schritt, Vergleichsoperatoren mit `True` oder `False` als Ergebnis, logische Operatoren zum Verknüpfen von Bedingungen und Textoperatoren.

```python
print(7 / 2, 7 // 2, 7 % 2, -7 // 2)   # 3.5 3 1 -4
summe = 0
summe += 5                              # 5
print(18 <= 30 <= 65)                   # True
print(True and False, not True)         # False False
```

**Das Wichtigste:** Bei der Division gibt es drei Varianten, und die musst du sicher auseinanderhalten. `/` liefert immer einen `float`, auch bei `6 / 3`, das `2.0` ergibt. `//` ist die ganzzahlige Division und rundet ab, zur kleineren Zahl hin. `%` liefert den Rest und ist praktisch für Fragen wie „gerade oder ungerade?“. Die logischen Operatoren heißen in Python `and`, `or` und `not`, nicht `&&`, `||` und `!`. Vergleiche lassen sich verketten wie in der Mathematik: `18 <= alter <= 65` prüft beide Grenzen auf einmal. `==` vergleicht immer den Inhalt, auch bei Strings, und `is` brauchst du nur für die Prüfung auf `None`.

**Achtung:** `-7 // 2` ergibt `-4`, weil Python abrundet. Java schneidet stattdessen ab und kommt auf `-3`. `x++` gibt es nicht, das ist ein `SyntaxError`. Gemeiner ist `++x`: Das ist gültiges Python, bedeutet aber nur zweimal das Vorzeichen Plus, also passiert nichts. `ruff` findet diese Falle. Schließlich ist `alter == "30"` bei `alter = 30` falsch, weil die Zahl 30 nicht der Text „30“ ist.

#### Strings, f-Strings und Typumwandlung

**Was ist das?** Mit Strings kannst du mehr anstellen, als sie nur auszugeben. Mit `+` verkettest du sie, mit `*` wiederholst du sie, `len()` liefert die Länge und `in` prüft, ob ein Teil enthalten ist. Mit eckigen Klammern greifst du auf einzelne Zeichen oder Ausschnitte zu, wobei die Zählung bei 0 beginnt und negative Zahlen von hinten zählen. Um Werte in Text einzubauen, nutzt du **f-Strings**: Alles in geschweiften Klammern wird ausgewertet und eingesetzt, auch Rechnungen. Wenn Typen nicht zusammenpassen, rufst du den Zieltyp wie eine Funktion auf, etwa `int("42")` oder `str(36)`.

```python
"Hallo"[1:3]                 # "al"
f"Preis: {3.5:.2f} €"        # "Preis: 3.50 €"
int(9.99)                    # 9 – schneidet ab
"Alter: " + 36               # TypeError
"Alter: " + str(36)          # funktioniert
```

**Das Wichtigste:** Python wandelt nur zwischen Zahlen automatisch um, und zwar immer zum „größeren“ Typ hin (`bool` → `int` → `float`). Deshalb ergibt `5 + 2.0` den Wert `7.0` und `True + 1` den Wert 2. Text und Zahl mischt Python dagegen nie von selbst, `"Alter: " + 36` ist ein `TypeError`. Genau das ist mit „stark typisiert“ gemeint: Python rät nicht, was du meinst. `int()` schneidet Nachkommastellen ab, statt zu runden, für echtes Runden gibt es `round()`.

**Achtung:** Das Geld-Beispiel der Folien solltest du kennen. `19.99 * 100` ergibt intern `1998.9999999999998`, und `int()` macht daraus 1998, also fehlt ein Cent. `round()` hilft im Einzelfall. Für Rechnungen und Buchhaltung nimmst du `Decimal("19.99")`, und zwar mit dem Wert als Text, damit er gar nicht erst ungenau wird. Auch `round` hat Tücken: `round(2.675, 2)` ergibt wegen der binären Darstellung 2.67, nicht 2.68.

#### Syntax vs. Semantik und Fehlermeldungen

**Was ist das?** Zum Schluss geht es darum, was schiefgehen kann. **Syntax** ist die Grammatik einer Sprache, also die Form: Klammern, Doppelpunkte, Einrückungen. **Semantik** ist die Bedeutung, also was der Code tatsächlich bewirkt. Ein Programm kann syntaktisch einwandfrei sein und trotzdem etwas ganz anderes tun als gedacht.

**Das Wichtigste:** Die Folien unterscheiden vier Fehlerarten danach, wann sie auffallen. Ein **Syntaxfehler** wie eine fehlende Klammer verhindert schon den Start. Ein **Typfehler** wie `"Alter: " + 36` wird von `ty` vorher gefunden, sonst bricht das Programm beim Ausführen ab. Ein **Laufzeitfehler** wie eine Division durch null tritt erst während des Ablaufs auf. Ein **Logikfehler** wie ein Minus statt Plus fällt nie automatisch auf, den findest du nur durch Nachdenken und Testen. Fehlermeldungen (Tracebacks) liest du **von unten nach oben**: Die letzte Zeile sagt, was passiert ist, darüber steht, in welcher Datei und Zeile, und das `^` markiert die genaue Stelle.

**Achtung:** In den Übungen steht `durchschnitt = 5 + 2 / 2` mit der Erwartung 3.5. Heraus kommt 6.0, weil Punkt- vor Strichrechnung gilt. Python meldet hier nichts, es ist ein klassischer Semantikfehler. Richtig wäre `(5 + 2) / 2`.

#### Daten und Information

**Was ist das?** Daten sind Rohwerte ohne Bedeutung, etwa das Bitmuster für 42. Erst mit Kontext („Kontostand in Euro“) werden sie zur Information, daraus entsteht Wissen („Die Kinokarte kostet 14 €, das reicht“) und schließlich eine Handlung („Ich gehe ins Kino“). Das Temperatur-Beispiel zeigt, wie viel der Kontext ausmacht: 7 Grad sind in Deutschland kalt, in Kanada eher mild, und in Fahrenheit entsprechen sie etwa −13 °C.

**Das Wichtigste:** Die Kette Daten → Information → Wissen → Handlung kommt heute in VL02 gleich wieder, dort als syntaktischer, semantischer und pragmatischer Aspekt.

**Achtung:** „Daten“ und „Information“ sind in der Klausur keine Synonyme.

#### Digitalisierung, IT-Infrastruktur und Cloud

**Was ist das?** Digitalisierung lässt sich auf drei Arten sehen. *Betriebswirtschaftlich* heißt sie, mit Daten und Algorithmen neue oder bessere Prozesse, Produkte und Geschäftsmodelle zu schaffen. *Gesellschaftlich* heißt sie, Lebens- und Arbeitswelt auf eine digitale Ebene zu übertragen. *Technisch* heißt sie, analoge Signale in binäre Werte umzuwandeln. Die wirtschaftlichen **Phasen der Digitalisierung** gehen von einzelnen Funktionen, etwa der automatischen Rechnung, bis zur weltweiten Vernetzung mit Kunden und Lieferanten. Eine heutige IT-Infrastruktur besteht aus sieben Komponenten: Hardware, Betriebssysteme, Datenspeicherung, Netzwerke, Anwendungen, Internet und Beratung bzw. Systemintegration.

**Das Wichtigste:** Die sieben Komponenten und die drei Sichtweisen stehen beide in der Rückschau, also lern sie als Liste. Bei der Cloud solltest du die Anbieter kennen: AWS, Azure, Google Cloud und STACKIT von der Schwarz-Gruppe.

**Achtung:** Die Phasen der Digitalisierung (wirtschaftliche Sicht) sind nicht dasselbe wie die fünf Epochen der IT-Infrastruktur (technische Sicht).

#### Treiber: Moore, Speicher, Netze

**Was ist das?** Gordon Moore sagte 1965 voraus, dass sich die Zahl der Transistoren pro Chip verdoppelt, zuerst jährlich, später alle zwei Jahre. Die geläufigen Fassungen „Die Rechenleistung verdoppelt sich alle 18 Monate“ und „Der Preis für Rechenleistung halbiert sich alle 18 Monate“ sind Interpretationen anderer. Dazu kommt, dass Speicher exponentiell billiger wird und die IPv4-Adressen aufgebraucht sind.

**Das Wichtigste:** Beide 18-Monats-Interpretationen stehen ausdrücklich in der Rückschau. Du solltest sie nennen können und wissen, dass sie nicht von Moore selbst stammen.

**Achtung:** Bei Metcalfe ist n·(n−1) quadratisch, nicht exponentiell.

### Heute voraussichtlich: Grundlegende Konzepte, Teil 1 – Zahlensysteme und Logik
*Grundlage: Folien „GIT VL02 v2“ (157 Folien), seit heute in Moodle. Die Folien reichen für heute und den 14.10. Dass heute ungefähr der erste Teil bis zu den Logikgattern (Folie 69) drankommt, ist geschätzt. Sicherheit: hoch für das Material, mittel für die Aufteilung.*

Teil II des Kurses schaut aus der Vogelperspektive auf drei Fragen: Wie rechnen Computer, wie funktioniert Programmierung, und welche Algorithmen werden im Betrieb am meisten genutzt? Heute geht es vermutlich um die erste Frage, und das baut logisch aufeinander auf. Zuerst klärt die Vorlesung, wie ein Rechner Information überhaupt darstellt, nämlich als Bits. Dann geht es darum, wie man Zahlen in verschiedenen Systemen schreibt und umrechnet, wie negative Zahlen funktionieren und wie man mit Logikgattern aus Bits rechnet. Am Ende steht die Antwort auf „Wie rechnet ein Computer?“: mit Transistoren als Schaltern, die zu Gattern verbunden sind, und die zu Addierern.

#### Wie Information im Rechner steckt

**Was ist das?** Ein Rechner kennt nur zwei Zustände: Spannung (1) oder keine Spannung (0). Ein solcher Zustand ist ein **Bit**, und 8 Bit ergeben ein **Byte**. Alles andere, also Zahlen, Text oder Bilder, muss erst in Bits übersetzt werden. Das nennt man **Kodierung**, und Sender und Empfänger müssen dieselbe Kodierung kennen. Die Folien zeigen das an der **Arecibo-Botschaft** von 1974. Sie besteht aus 1669 Bits ohne Gebrauchsanweisung. Wer erkennt, dass 1669 = 23 × 73 ist, ordnet die Bits als Rechteck an, und es entsteht ein Bild. Erst Kontext macht aus Daten Information, genau wie in VL01.

**Das Wichtigste:** Information hat drei Aspekte. Der **syntaktische** Aspekt ist die Form; sie entspricht dem *Typ* einer Variable. Der **semantische** Aspekt ist die Bedeutung; sie sollte sich im *Namen* der Variable widerspiegeln. Der **pragmatische** Aspekt ist die Frage, was man damit tut. Die Verarbeitung folgt dem **EVA-Prinzip**: Eingabe, Verarbeitung, Ausgabe (englisch IPO).

**Achtung:** Die Folien rechnen mit 1 KB = 1024 Byte. Streng genommen heißt das KiB, und 1 KB wären 1000 Byte. Wenn das in der Klausur drankommt, nimm die Zahlen des Dozenten.

#### Zahlensysteme und Umrechnen

**Was ist das?** In einem Stellenwertsystem hängt der Wert einer Ziffer von ihrer Position ab. Dezimal 235 heißt 2·100 + 3·10 + 5·1. Dasselbe Prinzip gilt mit anderen Basen. Binär (Basis 2) ist 235 = `11101011`, also 128+64+32+8+2+1. Oktal (Basis 8) ist 235 = 353, hexadezimal (Basis 16, Ziffern 0–9 und A–F) ist 235 = EB. Hexadezimal begegnet dir in CSS-Farbcodes wie `#1a0dab`, oktal in Transpondercodes der Luftfahrt.

**Das Wichtigste:** Zwei Rechenwege musst du sicher können. **Von dezimal in eine andere Basis** teilst du immer wieder durch die Basis und liest die Reste **von unten nach oben**: 235 : 2 = 117 Rest 1, 117 : 2 = 58 Rest 1, … bis 0, ergibt `11101011`. **Von binär nach oktal oder hex** bildest du von rechts Gruppen zu 3 bzw. 4 Bit: `1110 1011` → E B. Die Übungsaufgaben aus den Folien mit Lösungen: 458 = `111001010`₂ = 712₈ und `10010010`₂ = 222₈ = 92₁₆.

**Achtung:** Die Reste liest du rückwärts, das ist der häufigste Fehler. Bei Hex musst du A = 10 bis F = 15 sicher im Kopf haben. Der Dozent schreibt dazu selbst: „Das ist Übungssache“ und „Üben!!“.

#### Binär rechnen und negative Zahlen

**Was ist das?** Binär addierst du wie schriftlich im Dezimalsystem, nur mit einer Regel mehr: 1 + 1 = 0 mit Übertrag 1. So wird `0100 0001` (65) + `0101 1010` (90) zu `1001 1011` (155). Für negative Zahlen nutzen Rechner das **Zweierkomplement**: alle Bits umdrehen (das ist das Einerkomplement) und dann 1 addieren. Mit 5 Bit ist 9 = `01001`, umgedreht `10110`, plus 1 ergibt −9 = `10111`. Der Trick dabei: Subtraktion wird zur Addition. 14 − 9 rechnest du als `01110` + `10111` = `(1)00101` = 5, den Übertrag ganz links wirfst du weg.

**Das Wichtigste:** Das Zweierkomplement hat zwei Vorteile gegenüber dem Einerkomplement. Es gibt nur **eine Null**, das Einerkomplement hat +0 und −0. Und man braucht **keine Sonderfälle**: Plus und Minus laufen über dieselbe Addierschaltung. Deshalb ist es der Standard. Das höchste Bit zeigt das Vorzeichen, 1 heißt negativ.

**Achtung:** Beim Zweierkomplement muss die Bitbreite feststehen, also 5 Bit, 8 Bit usw. Positive Zahlen bleiben unverändert, nur negative werden umgewandelt. Wird der Wertebereich überschritten, gibt es einen **Überlauf**. Bei Java-Typen wie `int` passiert das, bei Python-`int` nicht, das kennst du aus Programmierung VL 2.

#### Boolesche Algebra und Logikgatter

**Was ist das?** George Boole hat im 19. Jahrhundert eine Algebra mit nur zwei Werten entwickelt: wahr (1) und falsch (0). Sie ist die Grundlage aller Rechner-Hardware. **AND** ist nur wahr, wenn alle Eingänge wahr sind, wie zwei Schalter hintereinander (Reihenschaltung). **OR** ist wahr, wenn mindestens einer wahr ist, wie zwei Schalter nebeneinander (Parallelschaltung). **NOT** kehrt den Wert um. In Chips übernehmen **Transistoren** die Rolle der Schalter, Milliarden davon auf einem Fingernagel. Insgesamt gibt es sieben Gatter: AND, OR, NOT, XOR („ungleich“), NAND, NOR und XNOR („gleich“).

**Das Wichtigste:** **NAND allein reicht**, um jede andere Verknüpfung zu bauen (genauso NOR). Das vereinfacht die Chipfertigung. Die Übung dazu lautet, AND nur aus NAND-Gattern zu bauen. Begründet wird das mit den **De-Morgan-Gesetzen**: ¬(a ∧ b) = ¬a ∨ ¬b. Am Ende verbindet sich alles zum **Halbaddierer**: Zwei Bits werden addiert, die Summe ist A XOR B, der Übertrag ist A AND B. Ein **Volladdierer** nimmt noch einen Übertrag von der vorherigen Stelle auf. Damit ist die Frage „Wie rechnet ein Computer?“ beantwortet: Transistoren bilden Gatter, und Gatter bilden Addierer.

**Achtung:** Übe die Wahrheitstabellen, vor allem XOR (1 nur bei ungleichen Eingängen) und NAND (0 nur, wenn beide Eingänge 1 sind). In den Übungen bestimmst du aus einer Tabelle den booleschen Ausdruck und baust daraus eine Schaltung. Auf der Exkurs-Folie zum Flipflop wirkt die Zuordnung von Set und Reset in der Tabelle vertauscht, im Zweifel nachfragen.
