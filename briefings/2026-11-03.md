### Ziele von Standortentscheidungen

**Was ist das?** Ein Unternehmen entscheidet, an wie vielen und an welchen Orten es produziert und verkauft. Beispiel: Ein Zulieferer baut sein Werk direkt neben das Autowerk, damit er „just in time“ liefern kann, also genau dann, wenn die Teile gebraucht werden.

**Das Wichtigste:** Es gibt drei Kategorien:

- **Wachstum:** einen Standort neu errichten oder erweitern
- **Strukturveränderung:** Standorte aufteilen, verlagern oder zusammenlegen
- **Schrumpfung:** einen Standort stilllegen

**Achtung:** Genau das ist **Musterklausur-Aufgabe 8 (6 Punkte)**. Schreib zu jeder Kategorie eine Erklärung **und** ein Beispiel.

### Standortstruktur und Standortfaktoren

**Was ist das?** Die Frage ist, welche Funktion an welchen Ort gehört. Vertrieb und Kundendienst sitzen nah beim Kunden, Führung und Forschung meist zentral. Ein Fitnessstudio braucht viele lokale Standorte, ein Halbleiterwerk reicht einmal weltweit.

**Das Wichtigste:** Die Standortfaktoren fallen in drei Gruppen: **unternehmensbezogen**, **produktionsbezogen** und **absatzbezogen**. Zwei Begriffe dazu:

- **Herkunftsgoodwill:** der gute Ruf eines Herkunftslands, z. B. „Made in Germany“
- **Local content:** Ein Staat schreibt vor, dass ein Mindestanteil der Wertschöpfung im Inland entstehen muss.

Manche Unternehmen suchen bewusst die Konkurrenz (Autohäuser nebeneinander), andere meiden sie (Apotheke).

**Achtung:** Die drei Faktorgruppen nicht mit den drei Zielkategorien von oben verwechseln.

### Nutzwertanalyse

**Was ist das?** Ein Verfahren, um Standorte nachvollziehbar zu vergleichen. In Übung 26 kommt so heraus: **USA 660, Tschechien 630, Deutschland 555**.

**Das Wichtigste:** Die Schritte:

1. Kriterien festlegen, z. B. Lohnkosten, Steuern, Fachkräfte.
2. Die Kriterien gewichten, die Gewichte ergeben zusammen 100.
3. Jedem Standort pro Kriterium Punkte von 0 bis 10 geben.
4. Gewicht × Punkte rechnen und für jeden Standort aufaddieren.

**Achtung:**

- **Multiplizieren, nicht addieren.**
- Mehr Punkte heißt immer „besser erfüllt“, auch bei Kosten. Niedrige Kosten bekommen also viele Punkte.
- Die Methode ist subjektiv. Senkt man die Steuerpunkte der USA von 9 auf 7, liegt schon Tschechien vorn. Diese Prüfung heißt Sensitivitätsanalyse.

### Polymorphie

**Was ist das?** Dieselbe Zeile Code macht je nach Objekt etwas anderes:

```python
def kasse(zahlungsart: Zahlungsart, betrag: float) -> None:
    zahlungsart.bezahlen(betrag)   # Kreditkarte bucht ab, Rechnung schreibt eine Rechnung
```

**Das Wichtigste:** Python sucht die Methode zuerst in der Klasse **des Objekts**. Neue Unterklassen funktionieren deshalb sofort, ohne dass du `kasse()` änderst. In Übung 3 ergeben die Personalkosten **28.850 €**, mit zwei Werkstudenten **31.250 €**, und `personalkosten()` bleibt dabei unverändert.

**Achtung:** Die **Typangabe** bestimmt, was `ty` erlaubt. `zahlungsart.nummer` ist ein Fehler, weil nicht jede Zahlungsart eine Nummer hat. Erst mit `isinstance` prüfen.

### Duck Typing

**Was ist das?** Python prüft beim Aufruf nur, **ob die Methode da ist**. Ein `Gutschein`, der nicht von `Zahlungsart` erbt, aber `bezahlen()` hat, läuft trotzdem. Der Name kommt von „Wenn es quakt wie eine Ente, ist es eine Ente.“

**Achtung:** `ty` meldet hier trotzdem `invalid-argument-type`, weil der Typ nicht passt.

### Abstrakte Klassen

**Was ist das?** Eine Vorlage mit Pflichtmethoden, von der man selbst **keine Objekte** erzeugen kann:

```python
from abc import ABC, abstractmethod

class Geraet(ABC):
    @abstractmethod
    def status(self) -> str: ...
```

**Das Wichtigste:** Jede Unterklasse muss `status()` selbst schreiben. Ein Tipp: Wenn `__repr__` `type(self).__name__` benutzt, steht automatisch der richtige Klassenname da, auch bei Unterklassen.

**Achtung:**

- Der `TypeError` kommt schon beim **Erzeugen** eines Objekts, nicht erst beim Aufruf einer Methode.
- Eine Unterklasse, der eine abstrakte Methode fehlt, bleibt selbst abstrakt.

### Fähigkeiten statt Interfaces

**Was ist das?** Eine Klasse hat eine Kategorie und beliebig viele Fähigkeiten:

```python
class Laptop(Geraet, Aufladbar, Netzwerkfaehig): ...
```

Ein Laptop **ist ein** Gerät und **kann** aufladen und ins Netzwerk. Geprüft wird mit `isinstance(x, Aufladbar)`. Das ist der Kern der Geräteverwaltung in Übung 4–5.

**Achtung:** Ohne die `isinstance`-Prüfung gibt es einen `AttributeError`, sobald ein Gerät die Fähigkeit nicht hat.
