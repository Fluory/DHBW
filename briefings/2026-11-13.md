### Rückblick: Termin 8 (06.11.) – Rest OOP II

*Polymorphie, abstrakte Klassen und Fähigkeiten, also genau das, was der Kaffeeshop in Stufe 2 braucht.*

#### Polymorphie

**Was ist das?** Dieselbe Zeile Code macht je nach Objekt etwas anderes. Die Kasse ruft immer `zahlungsart.bezahlen(betrag)` auf. Bei einer Kreditkarte wird abgebucht, beim Rechnungskauf eine Rechnung geschrieben.

**Das Wichtigste:**

- Polymorphie = Überschreiben in Unterklassen + Code, der nur die Oberklasse kennt.
- `@override` markiert eine überschriebene Methode, `ty` prüft dann den Namen.

**Achtung:** Welche Methode läuft, entscheidet das **Objekt**, nicht die Typangabe der Variable.

#### Abstrakte Klassen

**Was ist das?** Eine Klasse mit `ABC` und mindestens einer `@abstractmethod` ist ein Bauplan, von dem man selbst kein Objekt anlegen kann. Erst die Unterklassen füllen die Methode.

```python
from abc import ABC, abstractmethod

class Zahlungsart(ABC):
    @abstractmethod
    def bezahlen(self, betrag): ...

Zahlungsart()  # TypeError: Can't instantiate abstract class
```

**Das Wichtigste:**

- Jede Unterklasse **muss** alle abstrakten Methoden überschreiben, sonst ist sie selbst nicht anlegbar.

**Achtung:** Der `TypeError` kommt beim **Anlegen** des Objekts, nicht schon beim Schreiben der Klasse.

#### Fähigkeiten

**Was ist das?** Kleine abstrakte Klassen wie `Aufladbar` oder `Netzwerkfaehig`, die eine Klasse zusätzlich erbt: `class Laptop(Geraet, Aufladbar, Netzwerkfaehig)`.

**Das Wichtigste:** Eine Kategorie (`Geraet`) plus beliebig viele Fähigkeiten.

**Achtung:** Fähigkeiten haben nur abstrakte Methoden, keine Attribute.

#### Das Projekt

**Was ist das?** Zu zweit an einem Rechner, ohne KI, schreibt ihr einen Onlineshop für die Kommandozeile. Man sieht das Sortiment, sucht, legt etwas in den Warenkorb und bestellt. **Ziel: Bei jedem Team läuft mindestens Stufe 1.**

**Das Wichtigste:**

- Wechselt euch etwa alle 30 Minuten ab. **Beide** müssen jede Zeile erklären können.
- Prüfen mit `uv run ruff check .` und `uv run ty check`.

**Achtung:** Nicht alles auf einmal schreiben. Erst `lager.py` fertig und getestet, dann `warenkorb.py`, dann das Menü.

#### Stufe 1, Teil 1: das Lager

**Was ist das?** Eine Klasse mit der Produktliste und drei Methoden: `anzeigen()`, `finden(nummer)` und `suchen(text)`.

```python
def finden(self, nummer: int) -> Produkt | None:
    for produkt in self.produkte:
        if produkt.nummer == nummer:
            return produkt
    return None
```

**Das Wichtigste:** `finden` ist das Finden-Muster, `suchen` das Sammeln-Muster mit `text.lower() in produkt.name.lower()`.

**Achtung:** `return None` steht **nach** der Schleife, nicht im `else`.

#### Stufe 1, Teil 2: der Warenkorb

**Was ist das?** `Kunde` und `Position` als `@dataclass`, dazu der `Warenkorb` mit einer Liste von Positionen. Eine Position ist zum Beispiel „2 x Kaffee: 30.92 Euro“.

**Das Wichtigste:**

- `hinzufuegen` gibt `False` zurück, wenn Menge im Korb plus neue Menge größer als der Bestand ist.
- Liegt das Produkt schon im Korb, wird nur die Menge erhöht. So gibt zweimal Kaffee **eine** Position.

**Achtung:** French Press hat nur 3 auf Lager. Erst 3, dann 1 muss das zweite Mal abgelehnt werden.

#### Stufe 1, Teil 3: das Menü

**Was ist das?** Für jeden Menüpunkt eine Funktion, zum Beispiel `in_den_warenkorb(lager, korb)`. Die `while True`-Schleife mit `match` in `main()` bleibt dadurch kurz.

**Das Wichtigste:** Nummer und Menge immer mit `zahl_einlesen()` abfragen, dann gibt es bei `abc` keinen Absturz.

**Achtung:** Beim Bestellen die Summe merken, **bevor** der Korb geleert wird.

#### Stufe 2: Produktarten und Zahlungsarten

**Was ist das?** `Produkt` wird abstrakt mit `mwst_satz()`. Lebensmittel haben 7 %, Zubehör 19 %. Dazu kommen drei Zahlungsarten und eine `Bestellung`.

**Das Wichtigste:** Kontrolle: Kaffee kostet danach **13.90** statt 15.46, die French Press bleibt bei **24.87**.

**Achtung:** `korb.positionen.clear()` leert auch die Bestellung, weil beide dieselbe Liste sind. Richtig ist `korb.positionen = []`.
