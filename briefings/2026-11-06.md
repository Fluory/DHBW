### Rückblick Termin 7: Start OOP II

#### Vererbung und `super()`

**Was ist das?** Eine Unterklasse übernimmt alles von der Oberklasse und ergänzt Neues. Das passt nur bei einer „ist ein“-Beziehung: Ein Entwickler **ist ein** Mitarbeiter.

```python
class Entwickler(Mitarbeiter):
    def __init__(self, name, gehalt, sprache):
        super().__init__(name, gehalt)   # erst den Mitarbeiter-Teil bauen lassen
        self.sprache = sprache
```

**Das Wichtigste:**

- `isinstance(tom, Mitarbeiter)` ist `True`, auch wenn tom ein Entwickler ist.
- Schreibt die Unterklasse kein eigenes `__init__`, erbt sie das der Oberklasse.

**Achtung:** Wer `super().__init__` vergisst, bekommt den `AttributeError` erst später, nämlich beim ersten Zugriff auf `name`. ty meldet dabei nichts.

#### Überschreiben und `@override`

**Was ist das?** Eine Methode mit gleichem Namen in der Unterklasse ersetzt die alte. Mit `super()` kannst du die alte Version ergänzen statt sie ganz zu ersetzen:

```python
@override
def monatskosten(self):
    return super().monatskosten() + 150 * self.teamgroesse
```

So kostet Tom 6700 €.

**Das Wichtigste:** Python sucht eine Methode zuerst in der Klasse des Objekts, dann in den Oberklassen. Die Reihenfolge ist `Manager → Mitarbeiter → object`.

**Achtung:**

- Steht `@override` über einem Tippfehler wie `arbeitn`, meldet ty `invalid-explicit-override`.
- Überladen (gleicher Name, andere Parameter) gibt es in Python nicht.

### Heute: Polymorphie

**Was ist das?** Dieselbe Zeile Code macht je nach Objekt etwas anderes:

```python
def kasse(zahlungsart: Zahlungsart, betrag: float) -> None:
    zahlungsart.bezahlen(betrag)   # Kreditkarte bucht ab, Rechnung schreibt eine Rechnung
```

**Das Wichtigste:**

- Kommt eine neue Klasse wie `Lastschrift` dazu, bleibt `kasse()` unverändert.
- Die **Typangabe** bestimmt, was ty erlaubt. Das **Objekt** bestimmt, welche Methode läuft.

**Achtung:**

- `zahlungsart.nummer` ist ein ty-Fehler, weil nicht jede Zahlungsart eine Nummer hat. Prüf vorher mit `isinstance`.
- **Duck Typing:** Ein `Gutschein` mit eigener `bezahlen()`-Methode läuft auch ohne Vererbung, aber ty meldet `invalid-argument-type`.

### Heute: Abstrakte Klassen

**Was ist das?** Eine abstrakte Klasse ist eine Vorlage mit Pflichtmethoden. Von ihr kann man selbst keine Objekte erzeugen.

```python
from abc import ABC, abstractmethod

class Geraet(ABC):
    @abstractmethod
    def status(self) -> str: ...
```

**Das Wichtigste:** Du brauchst **beide Zutaten**: `ABC` als Oberklasse **und** `@abstractmethod`.

**Achtung:** Der `TypeError` kommt schon beim **Erzeugen** (`Geraet()`), nicht erst beim Aufruf von `status()`.

### Heute: Fähigkeiten und `__repr__`

**Was ist das?** Eine Klasse hat **eine Kategorie** und beliebig viele **Fähigkeiten**:

```python
class Laptop(Geraet, Aufladbar, Netzwerkfaehig): ...
```

Ein Laptop **ist ein** Gerät und **kann** aufladen und ins Netzwerk. Fähigkeiten haben nur abstrakte Methoden.

**Das Wichtigste:**

- Ob ein Gerät etwas kann, prüfst du mit `isinstance(x, Aufladbar)`.
- Benutzt `__repr__` den Ausdruck `type(self).__name__`, steht bei jeder Unterklasse automatisch der richtige Name.

**Achtung:** Rufst du eine Fähigkeit ohne `isinstance`-Prüfung auf, gibt es einen `AttributeError`, sobald ein Gerät sie nicht hat.
