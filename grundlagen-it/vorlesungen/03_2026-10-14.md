### Merge Sort und Rekursion (neu am 14.10.)
- **Merge Sort:** Array halbieren, beide Hälften für sich sortieren, die sortierten Hälften zusammenführen („Merge“).
  Aufwand **O(n log n)**.
- **Teile und Herrsche („Divide and Conquer“):** Eine Aufgabe wird in (zwei) gleichartige Teilaufgaben mit kleinerer
  (halbierter) Eingabe zerlegt.
- **Rekursion** ist der *Implementierungs*-Aspekt dazu: Eine Funktion ruft sich selbst (ggf. mehrfach) mit
  geänderten Eingabewerten auf.
- Beispiel **Fakultät:** N! = 1 · 2 · 3 · … · N, mit 1! = 1 und 0! = 1. Die Folie zeigt beide Varianten in Java:

```java
// iterativ
public static long fakite(int number) {
    long sum = 1;
    for (int i = 1; i <= number; i++) {
        sum = sum * i;
    }
    return sum;
}

// rekursiv
public static long fakrek(int number) {
    if (number == 1 || number == 0) {
        return 1;                       // Abbruchbedingung
    }
    else return number * fakrek(number - 1);
}
```

  Ablauf rekursiv: fakrek(4) = 4 · fakrek(3) = 4 · 3 · fakrek(2) = 4 · 3 · 2 · fakrek(1) = 4 · 3 · 2 · 1 = 24.
  Ohne **Abbruchbedingung** würde sich die Funktion endlos selbst aufrufen (Stack-Überlauf).
- Spielerisches Beispiel: **Türme von Hanoi** (n Scheiben brauchen 2ⁿ − 1 Züge; klassischer rekursiver Algorithmus).

### Programmiersprachen – vom Assembler zur Hochsprache (wahrscheinlich behandelt)
- Maschinensprache ist binär und prozessorabhängig; **Assembler** gibt den Befehlen symbolische Namen.
  Beispiele aus den Folien für „5 + 10 addieren“:
  - **6502** (1975; C64, Apple I/II, ca. 1 MHz): `LDA NUM1` (laden), `CLC` (Übertrag löschen), `ADC NUM2` (addieren), `STA RES` (speichern), `BRK`
  - **x86** (seit 1978; IBM-PC, Mac 2006–2020): `mov al, [num1]`, `add al, [num2]`, `mov [result], al`, Systemaufruf `int 0x80`
  - **68000** (1979; Atari ST, frühe Macs): `MOVE.L #5, D0`, `ADD.L D1, D0`, `MOVE.L D0, RESULT`
  - Gemeinsam: Werte in **Register** laden, rechnen, Ergebnis an eine **symbolische Adresse** zurückschreiben.
- Mit wachsender Komplexität wurde Assembler unübersichtlich → **höhere Programmiersprachen** auf Basis von
  Programmierparadigmen; sie brauchen ein Übersetzungsprogramm (Compiler oder Interpreter).
- **TIOBE-Index** misst die *Popularität* (Entwickler, Kurse, Anbieter, Suchanfragen) – nicht die beste Sprache und
  nicht die meisten Codezeilen.
- Entwicklungslinien: Abstraktion weg von der Maschine (BASIC 1964, `GOTO`) → **strukturierte Programmierung**
  (Pascal 1972, Niklaus Wirth; `function`, `procedure`) → Referenzen und dynamische Datentypen (`new`) →
  **Kapselung/Objektorientierung** (C++, Java) → **Speichersicherheit** (aktuell Rust).

### Fehlerquellen: Syntax, Semantik, Typen (wahrscheinlich behandelt)
- **Syntax** = korrekte Schreibweise (Java-Beispiel: fehlende `)` vor dem Semikolon → Compiler meldet Fehler).
- **Semantik** = korrekte Bedeutung (Java-Beispiel: Variablennamen passen nicht zu den zugewiesenen Werten – kein
  Fehler gemeldet, aber falsch).
- **Typ-Falle in Java:** `int z1 = 10; int z2 = 3; double res = z1 / z2;` ergibt **3.0**: erst `int / int` als
  Ganzzahldivision (3), dann Umwandlung in `double` (3.0). Richtig: `(double) z1 / z2` → 3.33…
  In „VL02 – final“ ist die Folie jetzt korrekt mit „3.0“ beschriftet (V4 hatte „3“).
  **Folienfehler F. 86:** `double(z1) / z2` ist kein gültiges Java (das wäre C++-Schreibweise); in Java heißt der
  Cast `(double) z1`. Außerdem `Int` statt `int` und fehlende Semikolons.
  (In Python liefert `/` immer `float` – siehe Programmierung VL 2.)

### Werkzeuge der Software-Entwicklung (wahrscheinlich behandelt)
- **Modellieren:** Ausschnitt der Realität abbilden, z. B. mit **UML**-Diagrammen oder über Datenstrukturen.
  Quelltext-Generatoren erzeugen aus Modellen Code-Rahmen.
- **Compilieren:** Befehle vorab in Maschinenbefehle für eine bestimmte Hardware übersetzen. Phasen:
  Quellprogramm → **Scanner** (lexikalische Analyse) → **Parser** (syntaktische Analyse, Syntaxbaum) →
  **semantische Analyse** und Optimierung → **Codeerzeugung** → Maschinenprogramm.
- **Interpretieren:** Befehle werden erst zur Laufzeit übersetzt und ausgeführt; Optimierung durch Vorübersetzen in
  maschinenunabhängigen **Bytecode** (Java, Python).
- **Linker:** verbindet getrennt compilierte Module (Objektdateien) zu einem ausführbaren Programm.
  **Statisch:** alles in eine große Datei, sicher vollständig. **Dynamisch:** Bibliotheken (DLL, Shared Library)
  erst zur Laufzeit → gemeinsame Nutzung und Austauschbarkeit, aber Abbruch, wenn eine Funktion fehlt.
- **Lader:** lädt den Maschinencode an eine Adresse (z. B. `0x4000`) und verschiebt alle Adressen um diesen Offset;
  beim Rechnerstart selbst an festen Adressen geladen (**Bootstrap**).
- **Debugger:** schrittweise Ausführung mit Haltepunkten (`Run`, `Step`, `Next`, `Cont`, `Undo`).
- **IDE** (z. B. Eclipse): Editor, Compiler und Debugger in einem.

## Wichtige Begriffe

- **Rekursion** – Funktion ruft sich selbst mit kleinerer Eingabe auf; braucht eine Abbruchbedingung
- **Teile und Herrsche (Divide and Conquer)** – Problem in gleichartige, kleinere Teilprobleme zerlegen (Merge Sort)
- **iterativ** – Lösung mit Schleife statt Selbstaufruf
- **Fakultät N!** – 1 · 2 · … · N, 0! = 1! = 1
- **Assembler / Register** – symbolische Maschinenbefehle / schneller Speicher im Prozessor
- **TIOBE-Index** – Popularität, nicht Qualität von Programmiersprachen
- **Syntax / Semantik** – Schreibweise (Compiler meldet Fehler) / Bedeutung (kein Fehler gemeldet, Ergebnis falsch)
- **Ganzzahldivision** – `int / int` schneidet ab, auch wenn das Ergebnis in `double` gespeichert wird
- **Scanner, Parser, Codeerzeugung** – Phasen eines Compilers
- **Compiler / Interpreter / Bytecode** – vorab übersetzen / zur Laufzeit übersetzen / maschinenunabhängige Zwischenform
- **statisches / dynamisches Linken** – alles in eine Datei / Bibliotheken zur Laufzeit (DLL)
- **Lader, Bootstrap** – Programm in den Speicher laden / Start beim Booten
- **Debugger, IDE** – schrittweise Ausführung / integrierte Entwicklungsumgebung
- **ASCII / UTF-8** (nicht belegt) – 7 Bit, 128 Zeichen / 1–4 Byte pro Zeichen, ASCII-kompatibel

## Aufgaben / Übungen

Lösungsskizzen der Routine – nicht aus den Folien, in der Vorlesung abgleichen.

- **Fakultät nachvollziehen:** fakrek(5) Schritt für Schritt auflösen. → 5 · 4 · 3 · 2 · 1 = 120; 5 Aufrufe,
  der letzte (number == 1) bricht ab.
- **Türme von Hanoi:** Wie viele Züge für 3 Scheiben? → 2³ − 1 = 7. Idee: n−1 Scheiben auf den Hilfsstab, größte
  Scheibe auf den Zielstab, n−1 Scheiben darauf.
- **Typ-Falle:** Was liefert `double r = 7 / 2;` in Java? → 3.0; mit `(double) 7 / 2` → 3.5.
- **Syntax oder Semantik?** `int alter = 1500000;` für ein Gehalt → Semantik (kein Compilerfehler);
  `int x = (3 + 4;` → Syntax.
- (Nicht belegt) „Grüße“ in UTF-8: G, r, e = 1 Byte; ü, ß = je 2 Byte → 7 Byte.
