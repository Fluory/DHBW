### Kontrollstrukturen
Ohne Kontrollstrukturen läuft ein Programm Zeile für Zeile ab. Zwei Ideen: **bedingte Ausführung** (nur wenn
etwas wahr ist) und **Wiederholung** (solange etwas gilt). Drei Grundformen des Programmflusses:

| Grundform | Was passiert? | Python |
|---|---|---|
| Sequenz | nacheinander, von oben nach unten | jede Zeile |
| Selektion | Bedingung prüfen, einen Weg wählen | `if`, `elif`, `else`, `match` |
| Iteration | wiederholen, solange eine Bedingung gilt | `while`, `for` |

### Blöcke
Ein `:` öffnet einen Block, alle folgenden Zeilen mit 4 Leerzeichen mehr gehören dazu; der Block endet, sobald
wieder weniger eingerückt wird. Ein Block ist **kein eigener Gültigkeitsbereich**: Variablen aus einem `if`-Block
leben danach weiter – existieren aber nicht, wenn der Block übersprungen wurde (`NameError`).

### Bedingte Anweisungen
```python
akku = 7
if akku < 10:
    print("Warnung: Akku fast leer!")

if regnet:
    print("Nimm den Schirm.")
else:
    print("Setz die Sonnenbrille auf.")

if temperatur < 0:
    print("Gefriert!")
elif temperatur < 20:
    print("Kühl.")
elif temperatur < 30:
    print("Angenehm.")
else:
    print("Heiß!")
```
- Kein Klammerpaar um die Bedingung, Doppelpunkt am Ende; `else` steht auf derselben Ebene wie `if`.
- Bei `if`–`else` läuft **genau ein** Block. `elif` ersetzt verschachtelte `if`s: Python prüft **nacheinander**
  und stoppt beim **ersten Treffer**.
- **`match`** (seit Python 3.10, Gegenstück zu Javas `switch`): vergleicht einen Wert mit festen Fällen, erster
  Treffer gewinnt, **kein `break`, kein Durchfallen**; `case _:` ist der Standardfall; mehrere Werte mit `|`:
  `case "A" | "B" | "C":`. `if`–`elif` bleibt der Normalfall, denn nur es kann Bereiche prüfen (`note < 3`).
- **Bedingter Ausdruck** (Kurzform, Java `b ? x : y`): `status = "offen" if betrag > 0 else "bezahlt"` –
  nur für die Wahl zwischen zwei Werten, nicht verschachteln; `ruff` schlägt die Kurzform selbst vor.
- **Wahrheitswerte beliebiger Werte:** als falsch gelten `False`, `None`, `0`, `0.0`, `""`, `[]`; alles andere
  ist wahr (auch `-1`, `"0"`, `" "`, `[0]`). Also: `if warenkorb:` prüft, ob die Liste nicht leer ist.
- **Stolperfallen:** fehlender Doppelpunkt → `SyntaxError: expected ':'`; fehlende Einrückung →
  `IndentationError`; nicht eingerückte Zeile gehört nicht mehr zum Block (läuft immer); `else` ohne direkt
  vorangehendes `if` → `SyntaxError`. Immer 4 Leerzeichen, nie Tabs mischen.

### Logische Operatoren
- `and` (Java `&&`), `or` (`||`), `not` (`!`). Beispiel: `if alter >= 18 and ticket_gueltig:`.
- XOR bei `bool`: `a != b`.
- **Rangfolge:** Klammern → Vergleiche → `not` → `and` → `or`. `a or b and not c` heißt `a or (b and (not c))`.
- Gesetze: **Kommutativ** (Reihenfolge egal), **Assoziativ** (Klammerung egal), **Distributiv**
  (`a and (b or c)` = `(a and b) or (a and c)`).
- **Kurzschlussauswertung:** Python wertet von links nach rechts aus und hört auf, sobald das Ergebnis feststeht.
  `x != 0 and 10 / x > 1` ist sicher, vertauscht gibt es `ZeroDivisionError` → **Absicherung nach vorn**.
- Verkettete Vergleiche: `0 < temperatur < 30`.

### Schleifen
- **`while`**: prüft zuerst, läuft dann; läuft gar nicht, wenn die Bedingung von Anfang an falsch ist. Der Zähler
  muss im Block verändert werden, sonst **Endlosschleife** (Abbruch mit Strg+C).
- **Kein `do`–`while`** in Python. Muster „mindestens einmal“: `while True:` … `if …: break` – typisch für
  Eingabeprüfung.
- **`for x in folge:`** – für jedes Element einmal, kein Zähler, kein `i++`. Zahlenfolgen mit
  **`range(start, stop, schritt)`**: `start` ist dabei, `stop` **nicht** (`range(1, 6)` → 1…5,
  `range(5, 0, -1)` → 5…1).
- `break` beendet die Schleife sofort, `continue` überspringt den Rest des aktuellen Durchlaufs.
  (`else` nach einer Schleife läuft, wenn sie ohne `break` endet – selten.)
- **Typische Fehler:** Endlosschleife, **Off-by-one** (eine Runde zu viel/zu wenig; `range(1, 5)` endet bei 4),
  falscher Startwert (Schleife läuft nie, ohne Fehlermeldung), falsche Schrittweite.

```python
n = 7
ergebnis = 1
for i in range(1, n + 1):   # n + 1, weil stop nicht dazugehört
    ergebnis = ergebnis * i
print(f"Fakultät von {n} ist: {ergebnis}")   # 5040
```

### Listen
- Geordnete Sammlung unter einem Namen, Zugriff über den Index; **keine feste Länge** (anders als Java-Arrays).
  Guter Stil: ein Typ pro Liste.
- Anlegen: `zahlen = [3, 6, 9]`, `leer: list[int] = []` (Typangabe nur bei leerer Liste nötig),
  `nullen = [0] * 5`; anhängen mit `append()`.
- Index ab **0**, negative Indizes von hinten (`noten[-1]` = letztes); außerhalb → `IndexError`.
  Keine automatischen Standardwerte wie in Java.
- Nützlich: `len`, `sum`, `min`, `max`, `in`, Slicing `noten[1:3]`, `sorted(noten)` (sortierte Kopie).
- Durchlaufen: Python-Weg `for note in noten:`; mit Position `for i, note in enumerate(noten):`; zwei Listen im
  Gleichschritt `for tag, wert in zip(tage, werte, strict=True):` (`ruff` verlangt `strict=`).
- **Mehrdimensional:** `matrix[1][2]`; durchlaufen mit verschachtelten Schleifen (`print(wert, end=" ")`).
- **Falle:** `[[0] * 4] * 3` erzeugt dreimal **dieselbe** Zeile (nur Verweise kopiert). Richtig:
  `for _ in range(3): matrix.append([0] * 4)`. `_` = Schleifenvariable, die man nicht braucht.
- **Tupel** `(3, 4)`: wie eine Liste, aber unveränderlich (`TypeError` bei Zuweisung) – für feste Zusammenstellungen.

## Wichtige Begriffe

- **Sequenz / Selektion / Iteration** – die drei Grundformen des Programmflusses
- **`elif`** – weitere Bedingung, geprüft nur, wenn vorherige falsch waren
- **`match` / `case _`** – Mehrfachauswahl über feste Werte / Standardfall
- **bedingter Ausdruck** – `A if Bedingung else B`
- **truthy / falsy** – Werte, die in Bedingungen als wahr bzw. falsch gelten
- **Kurzschlussauswertung** – Auswertung stoppt, sobald das Ergebnis feststeht
- **`range(start, stop, schritt)`** – Zahlenfolge, `stop` exklusiv
- **`break` / `continue`** – Schleife beenden / Durchlauf überspringen
- **Off-by-one** – Schleife läuft einmal zu oft oder zu wenig
- **Liste / Tupel** – veränderliche / unveränderliche Folge

### Abgleich mit den Musterlösungen (VL03_Loesungen.zip, 6 Dateien)
Die ZIP ist anders nummeriert als die Folien (`uebung1.py` … `uebung6.py`) und enthält **zusätzliche
Aufgaben**, die auf den Übungsfolien nicht stehen (vermutlich in der Vorlesung gestellt). In den Lösungen
steht statt `input()` jeweils ein fester Wert (für den automatischen Test), `input()` nur als Kommentar.

- **Übung 1 – Noten (nur in der ZIP):** Punkte → Note mit `if`/`elif` von oben nach unten (`>= 90` sehr gut,
  `>= 75` gut, `>= 60` befriedigend, `>= 50` ausreichend, sonst nicht bestanden). Grenzen testen mit je einem Wert
  auf und knapp unter der Grenze (90/89, 75/74 …). Merksatz: Steht `punkte >= 50` zuerst, bekommt auch 95 Punkte
  „ausreichend“ – **ohne** Fehlermeldung (Logikfehler). Dazu gerade/ungerade mit `% 2`.
- **Übung 2 – Parkgebühren:** Korrektur/Präzisierung zur Skizze: Der Rabatt gilt nur auf den Stundenpreis,
  **danach** kommt die Grundgebühr dazu, **zuletzt** der Deckel. Ungültiger Typ: Fehlermeldung im `case _:` und
  ein Merker `gueltig = False`, damit keine Kosten ausgegeben werden.
  ```python
  case "Transporter":
      kosten = stunden * 3.50
      if stunden >= 5:
          kosten *= 0.80
  ...
  if gueltig:
      kosten += GRUNDGEBUEHR
      if kosten > HOECHSTPREIS:
          kosten = HOECHSTPREIS
  ```
  Transporter, 6 h → 21,00 · 0,8 + 1,50 = **18,30 €**. Zusatz: `kosten *= 0.90 if stunden >= 10 else 1.0`.
- **Übung 3 – Stromkosten:** Korrektur/Präzisierung: „Staffelpreis“ heißt, **jede Stufe gilt nur für die kWh in
  ihrem Bereich** – nicht der ganze Verbrauch zum Preis der erreichten Stufe. Reihenfolge: Staffel → Grundpreis →
  Öko-Bonus → Obergrenze.
  ```python
  if verbrauch_kwh <= 100:
      kosten = verbrauch_kwh * PREIS_1
  elif verbrauch_kwh <= 300:
      kosten = 100 * PREIS_1 + (verbrauch_kwh - 100) * PREIS_2
  else:
      kosten = 100 * PREIS_1 + 200 * PREIS_2 + (verbrauch_kwh - 300) * PREIS_3
  ```
  180 kWh → 25,00 + 17,60 + 12,90 − 5,00 = **50,50 €**. Hinweis der Lösung: für echte Rechnungen `Decimal`.
  Zusatz Schaltjahr: `jahr % 4 == 0 and (jahr % 100 != 0 or jahr % 400 == 0)` (1900 False, 2000 True).
- **Übung 4 – `while`:** Countdown 10 … 1 + „Start!“ (nur ZIP); **gerade Zahlen** mit `while` und Zähler
  (`if zahl % 2 == 0: anzahl += 1`) → 50; Guthaben 1000 € bei 5 % bis zur Verdopplung (nur ZIP) →
  „Nach 15 Jahren: 2078.93 Euro“ – `while`, weil die Zahl der Durchläufe vorher unbekannt ist.
  Eingabeprüfung mit `while True:` … `break` als Kommentar.
- **Übung 5 – `for`/`range`:** 1–20 ohne Vielfache von 3 mit `continue`; erste durch 7 teilbare Zahl ab 100 mit
  `break` → 105 (beides nur ZIP); **Multiplikation** `for _ in range(a): ergebnis += b`; **Fibonacci** in zwei
  Varianten: mit Hilfsvariable `c` (erst 0 und 1 ausgeben, dann `range(ANZAHL - 2)`) oder per Tupel-Zuweisung
  `a, b = b, a + b` mit `range(ANZAHL)`. Zusatz: gerade Zahlen ohne `if` über `range(2, 101, 2)`, Anzahl mit
  `len(range(...))`.
- **Übung 6 – Temperaturen:** Ergänzung zur Skizze: Die Lösung gibt die Werte mit Wochentag aus
  (`zip(wochentage, temperaturen, strict=True)`) und startet das Maximum mit **`temperaturen[0]`, nicht mit 0**
  (sonst falsch bei lauter negativen Werten). Danach dasselbe mit `sum(...) / len(...)` und `max(...)`.
- **Sieb des Eratosthenes (in Übung 6):** `ist_prim = [True] * (N + 1)`, dann `ist_prim[0]` und `[1]` auf
  `False`; äußere Schleife `while p * p <= N` (Abbruch ab √N), Vielfache streichen **ab `p * p`**
  (kleinere wurden schon gestrichen – die Folie sagt „2·p, 3·p …“, beides ist richtig, die Lösung spart Arbeit):
  ```python
  if ist_prim[p]:
      for vielfaches in range(p * p, N + 1, p):
          ist_prim[vielfaches] = False
  ```
  Ausgabe mit `for zahl, prim in enumerate(ist_prim): if prim: ...`.
