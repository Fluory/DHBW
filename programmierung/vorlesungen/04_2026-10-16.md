### Funktionen definieren und aufrufen
Eine Funktion ist ein **abgeschlossener Codeblock mit Namen**, der eine Aufgabe erfüllt: Sie bekommt Eingaben
(Parameter), rechnet und liefert ein Ergebnis („kleine Maschine“). Bekannt sind schon `print()`, `len()`, `int()`,
`input()`. Vorteile: übersichtlich, wiederverwendbar, testbar.

```python
def begruessung(name: str) -> None:   # Definition: läuft noch nicht
    print(f"Hallo {name}!")

begruessung("Bob")                     # Aufruf: erst jetzt läuft der Rumpf
```

- `def` legt die Funktion nur an; der Rumpf läuft erst beim **Aufruf**. Python liest von oben nach unten, die
  Definition muss also vor dem ersten Aufruf stehen.
- **Parameter** = Platzhalter in der Definition (`name`), **Argumente** = konkrete Werte beim Aufruf (`"Bob"`).
  Ein Parameter verhält sich in der Funktion wie eine lokale Variable. Mehrere mit Komma: `def addiere(a: int, b: int)`.
- **Typannotationen an Parametern und Rückgabe schreiben wir immer.** Python ignoriert sie beim Ausführen
  (`begruessung(42)` läuft und gibt „Hallo 42!“ aus), `ty check` meldet aber `error[invalid-argument-type]`.

### Einstiegspunkt `main()`
Ab heute steht der Programmablauf in einer Funktion `main()`:

```python
def main() -> None:
    begruessung("Alice")

if __name__ == "__main__":
    main()
```

`__name__` ist `"__main__"`, wenn die Datei direkt gestartet wird (`uv run datei.py`). Wird sie von einer anderen
Datei **importiert**, läuft `main()` nicht los – ihre Funktionen lassen sich dann wiederverwenden und testen.
Entspricht `public static void main(String[] args)` in Java, ist in Python aber nur Konvention.

**Kommandozeilenargumente:** `import sys`, `sys.argv` ist eine Liste von `str`; `sys.argv[0]` ist der Skriptname,
die eigentlichen Argumente stehen in `sys.argv[1:]` (Java: `String[] args`).

### Rückgabewerte
```python
def addiere(a: int, b: int) -> int:
    summe = a + b
    return summe          # beendet die Funktion, Wert geht an den Aufrufer

def ist_gerade(zahl: int) -> bool:
    return zahl % 2 == 0

def min_max(zahlen: list[int]) -> tuple[int, int]:
    return min(zahlen), max(zahlen)

kleinste, groesste = min_max([4, 9, 2, 7])   # 2 9
```

- Rückgabetyp nach `->`; jeder Typ ist möglich (`int`, `bool`, `str`, `list` …).
- `return` beendet die Funktion **sofort**, Code danach läuft nicht mehr.
- „Mehrere Rückgabewerte“ = **ein Tupel**, das der Aufrufer wieder auspackt (wie `a, b = 1, 2` aus VL02).
- **Ohne `return` liefert jede Funktion `None`.** Bei `-> None` darf ein leeres `return` die Funktion vorzeitig
  beenden. Falle: Fehlt in einem Zweig das `return`, kommt dort `None` heraus:

```python
def vorzeichen(x: int) -> str:
    if x > 0:
        return "positiv"
    # x <= 0: kein return → None
```
  `ty` meldet: `error[invalid-return-type]: Function can implicitly return None …`.

**Aufrufstapel (Call Stack):** Beim Aufruf `addiere(5, 7)` legt Python einen neuen **Rahmen** (Stack Frame) an,
bindet `a = 5`, `b = 7`; `main` wartet. `return` gibt 12 zurück, der Rahmen verschwindet samt `a`, `b`, `summe`,
und `main` macht in derselben Zeile weiter.

**`break` vs. `return`:** `break` verlässt nur die aktuelle Schleife, der Rest der Funktion läuft weiter;
`return` verlässt die ganze Funktion, egal wie tief man in Schleifen steckt.

```python
for i in range(1, 11):
    if i == 5:
        break      # mit break: 1 2 3 4 + „Schleife beendet.“
    print(i)       # mit return: nur 1 2 3 4
print("Schleife beendet.")
```

### Gültigkeitsbereiche und Parameterübergabe
- Variablen aus einer Funktion sind **lokal**: Sie leben nur während des Aufrufs, außen gibt es `NameError`.
  Erinnerung: `if` und `for` schaffen keinen eigenen Gültigkeitsbereich – **Funktionen schon**.
- Namenssuche nach **LEGB**: Local → Enclosing (umschließende Funktion) → Global (Datei) → Built-in (`print`, `len`).
- Globale Werte **lesen** geht (`MWST_SATZ` in `brutto()`). Eine **Zuweisung** in der Funktion macht den Namen
  aber lokal:

```python
zaehler = 0
def erhoehe() -> None:
    zaehler += 1   # UnboundLocalError: cannot access local variable 'zaehler' …
```

- **Übergabe: Namen, keine Kopien** („call by object reference“). Der Parameter zeigt auf **dasselbe Objekt** wie
  das Argument.
  - `wert = wert + 1` bindet nur das lokale Schild neu → außen bleibt `zahl == 5`.
  - Bei Listen: `liste[0] = 99` ändert **das Objekt selbst** → außen sichtbar (**Nebeneffekt**);
    `liste = [7, 7, 7]` ist wieder nur eine lokale Neubindung. Ergebnis außen: `[99, 2, 3]`. Java verhält sich bei
    Arrays genauso.
- **Falle: veränderbarer Standardwert.** Der Standardwert wird **einmal beim Definieren** erzeugt und bei jedem
  Aufruf wiederverwendet (`ruff`: `B006`):

```python
def anhaengen(wert: int, liste: list[int] | None = None) -> list[int]:
    if liste is None:          # richtig: None als Standardwert,
        liste = []             # Liste erst im Rumpf anlegen
    liste.append(wert)
    return liste
```
  Mit `liste: list[int] = []` liefert der zweite Aufruf `anhaengen(2)` `[1, 2]` statt `[2]`.

- Funktionen rufen Funktionen auf (`quadratsumme` nutzt `quadriere`) → Hierarchie aus kleinen Bausteinen.
  Faustregel: **eine Funktion, eine Aufgabe, passt auf einen Bildschirm.**
- **Docstrings im Google-Stil** direkt unter der `def`-Zeile: erste Zeile ein Satz, dann `Args:` und `Returns:`;
  `help(netto)` im REPL zeigt ihn (Java: Javadoc).

### Standardwerte statt Überladung
Java löst „gleiche Aufgabe, andere Eingaben“ mit **Methodenüberladung**. **Python kennt keine Überladung:** Ein Name
zeigt auf genau ein Objekt, ein zweites `def addiere(...)` **überschreibt** das erste (`ruff`: `F811`); der Aufruf
mit zwei Argumenten scheitert dann mit `TypeError: addiere() missing 1 required positional argument: 'c'`.
Pythons Werkzeuge stattdessen:

```python
def brutto(netto: float, satz: float = 0.19) -> float:   # Standardwert
    return round(netto * (1 + satz), 2)

brutto(100)                    # 119.0  (Standardwert greift)
brutto(100, 0.07)              # 107.0  (Position)
brutto(satz=0.07, netto=100)   # 107.0  (Schlüsselwortargumente: Reihenfolge egal)
brutto()                       # TypeError: missing 1 required positional argument: 'netto'

def summe(*zahlen: int) -> int:   # *args: sammelt alles in ein Tupel
    ergebnis = 0
    for zahl in zahlen:
        ergebnis += zahl
    return ergebnis

summe(1, 2, 3, 4)   # 10, summe() → 0 (zahlen ist dann ())
```

- Parameter **mit** Standardwert stehen **hinter** denen ohne, sonst
  `SyntaxError: parameter without a default follows parameter with a default`.
- Zuordnung: erst der Reihe nach, fehlende bekommen den Standardwert, benannte finden ihr Fach über den Namen;
  fehlt ein Pflichtparameter, läuft die Funktion gar nicht erst los.
- Vergleich: andere Parameteranzahl → Standardwerte/`*args`; andere Typen → `int | float` oder getrennte Namen;
  Compiler wählt Methode → in Python gibt es pro Name genau eine Funktion. Unterschiedliche Aufgaben bekommen
  besser unterschiedliche Namen (`flaeche_kreis()`, `flaeche_rechteck()`).

### Imperative vs. applikative Programmierung
**Paradigma** = Denkmuster für den Entwurf von Algorithmen (weitere: objektorientiert, logisch, genetisch,
parallel, neuronal, agentenorientiert).

- **Imperativ** – das „Wie“: veränderbarer **Zustand** (Variablen), Anweisungen in fester Reihenfolge,
  Kontrollstrukturen (`for`, `while`, `if`, `match`). Schema: Variablen → `input` → Anweisungen → `output`;
  Beispiel Fakultät mit `while X > 1 do Y := Y · X; X := X - 1 od`.
- **Applikativ** (Grundlage: funktionale Programmierung) – das „Was“: Programme entstehen durch **Anwendung von
  Funktionen**; keine Nebenwirkungen (Ergebnis hängt nur von den Eingaben ab), Unveränderlichkeit, Funktionen als
  Argumente/Rückgabewerte, Funktionen höherer Ordnung (`map`, `filter`, `reduce`), **Rekursion statt Schleifen**.
  Funktionsdefinition `f(v1, …, vn) = t(v1, …, vn)` mit einem Term `t`.

Beispiel `h(p, q, x, y) = if p ∧ q then 4x + 2y else 5x − 3y fi`:

```python
def h(p: bool, q: bool, x: int, y: int) -> int:
    return 4 * x + 2 * y if p and q else 5 * x - 3 * y

h(True, False, 1, 3)   # 5 - 9 = -4
h(True, True, 2, 8)    # 8 + 16 = 24
```
**Fehler auf der Folie:** Im Code steht `else 5 * x - 3` – das `* y` fehlt. Mit dem Folien-Code käme
`h(True, False, 1, 3) == 2` heraus, nicht das angegebene `-4` (selbst nachgeprüft).

| | imperativ | applikativ |
|---|---|---|
| Denkschema | Wie mache ich es? | Was ist das Ergebnis? |
| Zustand / Variablen | ändern sich ständig | bleiben unverändert |
| Wiederholung | `for`, `while` | Rekursion |
| Nebenwirkungen | häufig | unerwünscht |

### Rekursion
**Rekursion:** Eine Funktion ruft **sich selbst** auf, um ein kleineres Teilproblem derselben Art zu lösen – so lange,
bis ein einfacher Fall erreicht ist. Zwei Pflichtteile:

1. **Abbruchbedingung** (Basisfall) – wann sie aufhört; verhindert endlose Rekursion.
2. **Rekursiver Aufruf** – mit einem **vereinfachten** Argument (das sich der Abbruchbedingung nähert).

```python
def fakultaet(n: int) -> int:
    """Berechnet n! rekursiv."""
    if n == 0:                       # Abbruchbedingung
        return 1
    else:
        return n * fakultaet(n - 1)  # rekursiver Aufruf

def summe_bis(n: int) -> int:        # summe_bis(7) → 28
    return 0 if n == 0 else n + summe_bis(n - 1)

def countdown(n: int) -> None:       # Rekursion ohne Rechenergebnis, nur Aktion
    if n == 0:
        print("Start!")
    else:
        print(n)
        countdown(n - 1)
```

**Im Speicher:** Jeder Aufruf bekommt einen eigenen Rahmen mit eigenem `n` auf dem Call Stack.
`fakultaet(3)` → **Abstieg**: 3 wartet auf `fakultaet(2)`, das auf `fakultaet(1)`, das auf `fakultaet(0)`;
`fakultaet(0)` liefert 1 → **Aufstieg**: 1·1 = 1, 2·1 = 2, 3·2 = 6.

**Ohne Abbruchbedingung** (oder wenn sie nie erreicht wird) wächst der Stapel immer weiter: n = 0, −1, −2 … bis
`RecursionError: maximum recursion depth exceeded` (Java: `StackOverflowError`). `sys.getrecursionlimit()` → etwa
**1000** Rahmen; Python macht **keine Tail-Call-Optimierung**, also bricht auch `fakultaet(5000)` ab. Für große `n`
iterativ lösen:

```python
def fakultaet_iterativ(n: int) -> int:
    ergebnis = 1                 # 0! = 1! = 1
    for i in range(1, n + 1):
        ergebnis *= i
    return ergebnis
```
In echten Programmen: `math.factorial(5)`.

- **Vorteile:** elegant und kurz bei selbstähnlichen Problemen (Fakultät, Fibonacci, Verzeichnisbäume,
  Sortieralgorithmen), mathematische Definitionen direkt umsetzbar, wenig Zustand und Hilfsvariablen.
- **Nachteile:** speicherintensiv (Rahmen pro Aufruf → `RecursionError`), langsamer als Schleifen (viele Aufrufe),
  schwerer zu debuggen, „rückwärts denken“ muss man lernen.

### Funktionen testen
- **`assert bedingung`** tut nichts, wenn die Bedingung stimmt, sonst `AssertionError`:
  `assert fakultaet(5) == 120`. Der Import `from fakultaet import fakultaet` klappt nur ohne Nebenwirkungen, weil
  `main()` hinter `if __name__ == "__main__":` steht.
- **pytest** (entspricht JUnit): Datei `test_….py` neben dem Code, jede Testfunktion beginnt mit `test_` und enthält
  ein oder mehrere `assert`.

```python
from fakultaet import fakultaet

def test_fakultaet_null() -> None:
    assert fakultaet(0) == 1

def test_fakultaet_fuenf() -> None:
    assert fakultaet(5) == 120
```

- Einrichten/Ausführen: `uv add --dev pytest` (einmal pro Projekt), dann `uv run pytest` – sucht alle `test_*.py`.
  Ausgabe: `.` = bestanden, `F` = fehlgeschlagen. Beispiel der Folie: steht aus Versehen `n + fakultaet(n - 1)` im
  Code, zeigt pytest `.FF` und `assert 16 == 120` mit `where 16 = fakultaet(5)` – also tatsächlicher vs. erwarteter
  Wert. (Nachgerechnet: 5+4+3+2+1+1 = 16, und `fakultaet(0) == 1` besteht weiterhin.)

## Wichtige Begriffe

- **Funktion** – benannter Codeblock mit Parametern und Rückgabewert
- **Parameter / Argument** – Platzhalter in der Definition / konkreter Wert beim Aufruf
- **Signatur** – Name, Parameter mit Typen und Rückgabetyp (`def f(a: int) -> int`)
- **`return`** – beendet die Funktion und liefert einen Wert; ohne `return` → `None`
- **`main()` / `if __name__ == "__main__":`** – Einstiegspunkt, der beim Import nicht losläuft
- **`sys.argv`** – Liste der Kommandozeilenargumente (alles `str`, Index 0 = Skriptname)
- **Aufrufstapel / Stack Frame** – pro Aufruf ein Rahmen mit eigenen lokalen Variablen
- **lokal / global, LEGB** – Gültigkeitsbereiche und Suchreihenfolge Local → Enclosing → Global → Built-in
- **`UnboundLocalError`** – Zuweisung in der Funktion macht einen Namen lokal, bevor er gelesen wird
- **call by object reference** – Übergabe von Verweisen auf Objekte, keine Kopien
- **Nebeneffekt** – Änderung außerhalb der Funktion ohne Rückgabewert (z. B. übergebene Liste ändern)
- **Standardwert** – `satz: float = 0.19`, gilt, wenn kein Argument kommt
- **Schlüsselwortargument** – Übergabe über den Namen: `brutto(netto=100, satz=0.07)`
- **`*args`** – beliebig viele Positionsargumente, gesammelt in einem Tupel
- **Überladung** – gibt es in Python nicht; zweites `def` überschreibt (`F811`)
- **imperativ / applikativ** – Zustand und Anweisungen („wie“) / Anwendung von Funktionen ohne Nebenwirkungen („was“)
- **Rekursion** – Funktion ruft sich selbst mit kleinerem Problem auf
- **Abbruchbedingung (Basisfall)** – Fall ohne Selbstaufruf
- **`RecursionError`** – Rekursionstiefe (≈ 1000) überschritten
- **`assert` / pytest** – Bedingung prüfen / Testwerkzeug, Dateien und Funktionen mit `test_`

   if index == len(zahlen) - 1:      # letztes Element

   rest = maximum(zahlen, index + 1)

## Typische Fehler / Fallen

- **Definition ≠ Aufruf:** `def` allein führt nichts aus; Funktion ohne Klammern (`main` statt `main()`) wird nicht
  aufgerufen.
- **`print` statt `return`:** Eine Funktion, die nur ausgibt, liefert `None` – `ergebnis = f(...)` ist dann `None`.
- **Fehlendes `return` in einem Zweig** → implizit `None` (`ty`: `invalid-return-type`).
- **Code nach `return`** läuft nie; `return` in einer Schleife beendet die ganze Funktion, `break` nur die Schleife.
- **Lokale Variable außen benutzen** → `NameError`; **globale Variable in der Funktion verändern** (`zaehler += 1`)
  → `UnboundLocalError`.
- **Neubindung vs. Veränderung:** `wert = wert + 1` / `liste = [...]` wirkt nur lokal, `liste[0] = 99` oder
  `liste.append(...)` ändert das Objekt des Aufrufers.
- **Veränderbarer Standardwert** `liste: list[int] = []` → Liste wird zwischen Aufrufen geteilt; `None` verwenden
  (`ruff` B006).
- **Reihenfolge der Parameter:** Pflichtparameter vor solchen mit Standardwert, sonst `SyntaxError`.
- **„Überladen“ mit zweitem `def`** überschreibt die erste Funktion (`F811`, dann `TypeError` beim Aufruf).
- **Annotationen werden zur Laufzeit nicht geprüft** – nur `ty` findet `begruessung(42)`.
- **Rekursion ohne erreichbare Abbruchbedingung** → `RecursionError` (z. B. `fakultaet(-1)` mit `if n == 0`;
  robuster wäre `if n <= 0`). Auch das Lösungs-`maximum([])` läuft so in einen `RecursionError`, weil
  `index == -1` nie eintritt (selbst getestet) – eine leere Liste ist nicht abgedeckt.
- **Naive Fibonacci-Rekursion** ist exponentiell langsam; `@functools.cache` oder iterativ lösen.
- **Rekursionstiefe ≈ 1000**, keine Tail-Call-Optimierung → für große `n` Schleife verwenden.
- **Testdatei-Namen:** pytest findet nur `test_*.py` mit Funktionen `test_…`.
- **Gleitkomma bei Tests:** `potenz(0.1, 3)` ergibt `0.0010000000000000002`, also nicht mit `== 0.001` testen

## Selbsttest-Quiz (Moodle)
„VL04_Quiz.html“ ([Link](https://moodle.heilbronn.dhbw.de/mod/resource/view.php?id=191321), gesehen am 23.10.):
interaktive Fragen in vier Kapiteln wie die Agenda. Die Notiz deckt alle Fragen ab; die lehrreichsten:

1. **`return` in der Schleife:** `for i in range(1, 11): if i == 4: return` – `print(i)` in `main()` gibt nur
   `1 2 3` aus, auch „Schleife beendet.“ danach kommt nicht mehr. `return` verlässt die ganze Funktion, `break`
   nur die Schleife.
2. **Neubindung vs. Veränderung:** `liste[0] = 99; liste = [7, 7, 7]` in der Funktion → außen `[99, 2, 3]`.
   Die Änderung am Objekt ist sichtbar, die neue Zuweisung an den Parameter nicht.
3. **Zwei `def addiere`:** Python wählt nicht passend aus; die zweite Definition ersetzt die erste, und
   `addiere(1, 2)` endet mit `TypeError` (fehlendes `c`). Kein `SyntaxError`, ruff meldet `F811`.
4. **Veränderbarer Standardwert:** `anhaengen(1)`, `anhaengen(2)` mit `liste: list[int] = []` → `[1]` und dann
   `[1, 2]`, weil der Standardwert nur einmal beim Definieren erzeugt wird.
5. **Rekursion reparieren:** `fakultaet` mit `return 0` als Basisfall liefert immer 0 – richtig ist `return 1`
   (0! = 1). Mit `+` statt `*` kommt `fakultaet(5) == 16` heraus, `fakultaet(0) == 1` stimmt zufällig weiter.
6. **pytest:** `.FF` = ein Test bestanden, zwei fehlgeschlagen; eine Testfunktion gibt nichts zurück, sie prüft mit
   `assert`. `main()` läuft beim Import nicht, weil es hinter `if __name__ == "__main__":` steht.
