### Kommentare und Docstrings
- Kommentar = Text, den Python ignoriert; richtet sich an Menschen. Er erklärt das **Warum**, das Was zeigt
  der Code selbst. `#` bis Zeilenende; mehrzeilig = mehrere `#`-Zeilen. Kein `/* … */` wie in Java.
- Docstring `"""…"""` beschreibt Funktion, Klasse oder Datei, Werkzeuge erzeugen daraus Doku. Im Kurs
  **Google-Stil**: Kurzbeschreibung, dann `Args:` und `Returns:` (ausführlich ab VL04).

```python
# Seit 2007 gilt der Regelsatz von 19 %      ← sinnvoll
brutto = netto * 1.19  # Multipliziere …     ← überflüssig

def kreisflaeche(radius: float) -> float:
    """Berechnet die Fläche eines Kreises.

    Args:
        radius: Radius in Metern, nicht negativ.

    Returns:
        Die Fläche in Quadratmetern.
    """
    return 3.14159 * radius**2
```

### Datentypen
- Bezug zur **DIKW-Pyramide** (Daten → Information → Wissen → Weisheit): Programme arbeiten auf der Ebene
  Daten, der Datentyp legt fest, welche Art von Daten vorliegt und welche Operationen erlaubt sind.
  `type(42)` → `<class 'int'>`.
- **Statisch** (Java, C#: Prüfung beim Kompilieren), **dynamisch** (Python, JS: beim Ausführen),
  **graduell** (Python mit Typangaben + `ty`: vor dem Ausführen) – im Kurs die dritte Variante.
- In Python ist jeder Wert ein Objekt, keine „primitiven“ Typen wie in Java.

| Typ | Beispiele | Hinweis | Java |
|---|---|---|---|
| `int` | `42`, `-7`, `1_000_000` | beliebig groß, kein Überlauf (`2 ** 100`) | byte/short/int/long |
| `float` | `3.14`, `-0.5` | 64 Bit, 15–16 Stellen; `0.1 + 0.2 == 0.3` ist `False` | double |
| `bool` | `True`, `False` | großgeschrieben | boolean |
| `str` | `"Hallo"`, `"A"` | unveränderlich; Zeichen = str der Länge 1; `ord("A")` = 65, `chr(66)` = `"B"` | String, char |
| `None` | `None` | „kein Wert“, nicht 0 und nicht `""`; `telefon: str \| None = None` | null |

- Faustregel: `int` für ganze Zahlen, `float` für Messwerte, `str` für alles, womit man nicht rechnet
  (PLZ, Telefonnummer). Für Geld `decimal.Decimal`.
- Ausblick: `list`, `tuple`, `dict`, `set`, `Enum`, eigene Klassen.

### Variablen und Konstanten
- Variable = **Name, der auf einen Wert zeigt** (Namensschild, nicht Box). Der Typ gehört zum Wert.
  Entsteht bei der ersten Zuweisung; keine Deklaration. `=` heißt „zeigt ab jetzt auf“.
  `zahl = zahl + 1`: erst rechts rechnen, dann neu zuweisen; alter Wert wird automatisch freigegeben.
- **Typangaben** `alter: int = 25`: Python ignoriert sie, `ty` prüft sie (`error[invalid-assignment]`).
  „Die Typangabe ist ein Versprechen. ty passt auf, dass Sie es halten.“
- Mehrfachzuweisung `breite, hoehe = 1920, 1080`; `x = y = 0`; Tauschen `a, b = b, a`.
- Typische Fehler: `NameError` bei nie zugewiesener Variable, bei falscher Großschreibung (`Zahl`) und bei
  bloßer Typangabe ohne Wert (`anzahl: int`); `wert = 3,5` ergibt Tupel `(3, 5)`.
- Gültigkeitsbereich: Variablen aus `if`-/Schleifenblöcken leben danach weiter, erst Funktionen schaffen
  eigene Bereiche (VL04). Falle: Wurde der Block nicht ausgeführt, existiert die Variable nicht.
- Namen: Buchstaben, Ziffern, `_`, nicht mit Ziffer beginnen, kein Schlüsselwort. Konventionen:
  `snake_case` (Variablen, Funktionen, Dateien), `UPPER_SNAKE_CASE` (Konstanten), `PascalCase` (Klassen);
  camelCase ist Java/JS, kebab-case ist in Python ungültig. Keine Umlaute (`groesse`). `ruff` prüft (Regeln N).
- **Konstanten**: Python hat kein `final`. `from typing import Final`, `MWST_SATZ: Final = 0.19`;
  `ty` meldet Neuzuweisung, Python verhindert sie zur Laufzeit nicht.

### Operatoren
| Kategorie | Operatoren |
|---|---|
| arithmetisch | `+ - * / // % **` |
| Zuweisung | `= += -= *= /= //= %=` |
| Vergleich | `== != < > <= >=` → bool |
| logisch | `and or not` (statt `&& \|\| !`) |
| Text | `+` (verketten), `*` (wiederholen), `in` |

- `/` liefert **immer** float (`6 / 3` → `2.0`). `//` rundet **ab** (`-7 // 2` → `-4`, Java: `-3`).
  `%` = Rest (`7 % 3` → 1, `9 % 3` → 0). Punkt vor Strich, `**` bindet am stärksten.
- Mini-Aufgabe: `x = 4; x *= 2; x -= 3; x //= 2` → 2.
- Kein `x++` (SyntaxError); `++x` ist zweimal Vorzeichen +, ändert nichts (`ruff` Regel B002).
- `==` vergleicht Inhalt (auch Strings, kein `.equals()`); `is` nur für `None`. `alter == "30"` → False.
- Verkettete Vergleiche: `18 <= alter <= 65`.

### Strings, f-Strings, Typumwandlung
- `len("Hallo")` → 5, `"python".upper()`, `"Hallo"[0]` → `"H"`, `[-1]` → `"o"`, `[1:3]` → `"al"`,
  `"ll" in "Hallo"` → True. Positionen ab 0.
- f-Strings: `f"{name} ist {alter} Jahre alt"`, `f"{preis:.2f} €"`, Rechnen in `{}` erlaubt.
- Umwandlung durch Aufruf des Typs: `int(9.99)` → 9 (schneidet ab!), `float(5)` → 5.0, `str(42)`,
  `int("42")` (ValueError bei ungültigem Text), `round(2.675, 2)` → 2.67, `round(9.5)` → 10.
- Automatisch nur zwischen Zahlen: bool → int → float (`5 + 2.0` → 7.0, `True + 1` → 2).
  Text + Zahl → `TypeError` („stark typisiert: Python rät nicht“).
- Geld: `int(19.99 * 100)` → 1998 (ein Cent weg), `round()` hilft; exakt: `Decimal("19.99")` (als Text übergeben).

### Syntax vs. Semantik
- Syntax = Grammatik/Form, Semantik = Bedeutung/Wirkung.

| Fehlerart | Beispiel | Wann bemerkt? |
|---|---|---|
| Syntaxfehler | `print("Hallo"` | vor dem Start |
| Typfehler | `"Alter: " + 36` | durch `ty` vorher, sonst TypeError |
| Laufzeitfehler | `a / b` mit `b = 0` | beim Ausführen (ZeroDivisionError) |
| Logikfehler | `5 - 3` statt `+` | nie automatisch |

- Traceback **von unten nach oben** lesen: letzte Zeile = Fehlerart, darüber Datei und Zeile, `^` = Stelle.

## Wichtige Begriffe

- **Docstring (Google-Stil)** – Funktionsbeschreibung mit `Args:` und `Returns:`
- **graduelle Typisierung** – Python + Typangaben, vorab geprüft von `ty`
- **Typangabe / Annotation** – `name: typ = wert`
- **`Final`** – markiert Konstanten, prüfbar durch `ty`
- **`//` / `%`** – ganzzahlige Division (abrunden) / Rest
- **f-String** – Werte direkt in Text einsetzen
- **`Decimal`** – exakte Dezimalzahlen für Geld
- **Syntax / Semantik** – Form / Bedeutung des Codes
