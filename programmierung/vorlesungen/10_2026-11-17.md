## Zusammenfassung

### Exceptions: was passiert, wenn etwas schiefgeht

**In einem Satz:** Mit `try` / `except` fängst du einen Laufzeitfehler ab, statt dass das Programm abstürzt.

**Stell dir vor:** `int("abc")` ist wie ein Automat, der statt einer Münze einen Knopf bekommt. Ohne `try` blockiert
der ganze Automat. Mit `try` sagt er „Bitte eine Münze“ und läuft weiter.

```python
def zahl_einlesen_sicher(text: str) -> int | None:
    try:
        return int(text)
    except ValueError:      # nur diesen Fehler abfangen
        return None

print(zahl_einlesen_sicher("42"), zahl_einlesen_sicher("abc"))   # 42 None
```

**Selbst einen Fehler auslösen** mit `raise`:

```python
def teilen(a: float, b: float) -> float:
    if b == 0:
        raise ValueError("Teilen durch 0 ist nicht erlaubt")
    return a / b

try:
    print(teilen(10, 4))     # 2.5
    print(teilen(1, 0))      # löst den Fehler aus
except ValueError as fehler:
    print("Fehler:", fehler) # Fehler: Teilen durch 0 ist nicht erlaubt
finally:
    print("fertig")          # läuft immer
```

**Die häufigsten Fehlerarten:**

| Fehler | Wann? | Beispiel |
|---|---|---|
| `ValueError` | Der Wert passt nicht | `int("abc")` |
| `TypeError` | Der Typ passt nicht | `"Preis: " + 5` |
| `IndexError` | Den Index gibt es nicht | `[1, 2, 3][5]` |
| `ZeroDivisionError` | Teilen durch 0 | `1 / 0` |
| `NameError` | Der Name ist unbekannt | Variable vertippt |

**Achtung:**
- Nicht einfach `except:` ohne Fehlerart schreiben, das versteckt auch echte Programmierfehler.
- Ein `SyntaxError` lässt sich nicht mit `try` abfangen. Das Programm startet dann gar nicht erst.

## Wichtige Begriffe
- **Exception** – Laufzeitfehler als Objekt, z. B. `ValueError`
- **try / except** – Fehler abfangen und weitermachen
- **raise** – selbst einen Fehler auslösen
- **finally** – läuft immer, ob Fehler oder nicht
