Aufgabe 1 · Grundlagen, Werkzeuge und Module

6 Punkte

1.1Eigenschaft „terminierend“ eines Algorithmus

Richtig: B. Er kommt bei jeder zulässigen Eingabe irgendwann zum Ende, nach endlich vielen Schritten. Merke das Trio: gleiche Eingabe, gleiches Ergebnis heißt determiniert; immer eindeutig festgelegter nächster Schritt heißt deterministisch.

1.2Was beim Start mit uv run passiert

Richtig: C. Python macht aus dem Quellcode Bytecode, und die virtuelle Maschine von Python arbeitet ihn ab. Es entsteht weder eine ausführbare Datei noch Java, und nichts geht an einen Server.

1.3Bedeutung von „dynamisch typisiert“

Richtig: D. Der Typ hängt am Wert, nicht am Namen. Ein Name darf später auf einen Wert anderen Typs zeigen. Typangaben prüft Python beim Ausführen nicht, und Text plus Zahl ergibt einen TypeError statt einer automatischen Umwandlung.

1.4Werkzeug, das einen falschen Argumenttyp vor dem Start meldet

Richtig: B. ty ist der Typprüfer. ruff kümmert sich um Stil und typische Fehler, pytest führt Tests aus, uv add fügt ein Paket hinzu.

1.5Gültiger Aufruf nach einem from … import

Richtig: B. Mit from math import ceil ist nur der Name ceil bekannt, nicht math. Für math.ceil(…) bräuchtest du import math, sonst kommt ein NameError.

1.6Erster Schritt, um ein Paket von pypi.org zu nutzen

Richtig: C. uv add im Projektordner lädt das Paket und trägt es in pyproject.toml ein. Andere bekommen mit uv sync denselben Stand. Python lädt nichts von selbst nach.

3.3(4 Punkte) Umsätze summieren: a) was passiert und warum, b) korrigierte Schleife

a) Das Programm stürzt mit IndexError ab und gibt gar nichts aus. Ursache 1: Der Zähler beginnt bei 1, also wird das erste Element (Index 0) nie addiert. Ursache 2: Wegen <= läuft die Schleife noch mit dem Index 3, die Liste hat aber nur die Indizes 0 bis 2.

b) Zum Beispiel direkt über die Elemente laufen (ergibt 3580):

summe = 0
for betrag in umsaetze:
    summe += betrag
print(summe)

Auch richtig: Index bei 0 starten und mit < vergleichen, oder for i in range(len(umsaetze)). Nur sum(umsaetze) ohne Schleife gibt 1 statt 2 Punkte.

Nur „IndexError“ ohne Ursache zählt ½ Punkt. Den kannst du hier nicht anhaken, merk ihn dir.

3.4(4 Punkte) Funktion versandkosten mit drei Preisstufen schreiben

def versandkosten(bestellwert: float) -> float:
    if bestellwert >= 50:
        return 0.0
    if bestellwert >= 20:
        return 2.9
    return 4.9

Kontrolle: 50.0 → 0.0, 20.0 → 2.9, 19.99 → 4.9, 80.0 → 0.0. Falle: Prüfst du zuerst auf 20, landet auch eine Bestellung über 80 Euro bei 2,90. Von unten mit < zu prüfen geht genauso. print statt return kostet 1 Punkt.

Aufgabe 4 · Funktionen und Parameter

12 Punkte

4.1Was return in einer Funktion bewirkt

Richtig: B. return beendet die Funktion sofort und liefert den Wert dorthin, wo sie aufgerufen wurde. Es gibt nichts aus und beendet nicht nur eine Schleife.

4.2Wo eine in der Funktion angelegte Variable gilt

Richtig: D. Sie ist lokal: Es gibt sie nur in dieser Funktion und nur, solange der Aufruf läuft. Draußen kennt niemand den Namen.

4.3Zwei def mit gleichem Namen, verschiedene Parameterzahl

Richtig: B. Python kennt keine Überladung. Die spätere Definition überschreibt die frühere, ein Aufruf mit zwei Argumenten scheitert dann mit TypeError. Besser: ein Parameter mit Standardwert.

4.4(5 Punkte) Rabatt-Funktion: a) drei Ausgaben, b) Liste ändert sich, Zahl nicht

a) 1. Ausgabe
a) 2. Ausgabe
a) 3. Ausgabe

a) [18.0, 45.0] · 10 · None. Beide Preise sinken um 10 %. Die Funktion hat kein return, darum ist ihr Ergebnis beim zweiten Aufruf None (die Liste wird dabei trotzdem nochmal verändert, das wird aber nicht mehr ausgegeben).

b) Beim Aufruf bekommt die Funktion keine Kopie, sondern einen zweiten Namen für dasselbe Listen-Objekt. Wer über den Index hineinschreibt, ändert genau diese eine Liste, und das sieht main. Die Zuweisung an prozent dagegen biegt nur den lokalen Namen der Funktion auf einen neuen Wert um, der Name in main zeigt weiter auf 10.

Aufgabe 5 · Objektorientierung

18 Punkte

5.1Was ein Objekt ist

Richtig: B. Ein Objekt ist ein konkretes Exemplar einer Klasse mit eigenen Attributwerten. Die Klasse ist der Bauplan dazu.

5.2Wann __init__ läuft

Richtig: C. Der Konstruktor läuft automatisch jedes Mal, wenn du mit Konto(…) ein neues Objekt erzeugst. Von Hand ruft man ihn nicht auf.

5.3Was ein Klassenattribut ist

Richtig: D. Es steht direkt im Klassenrumpf und gilt für alle Objekte gemeinsam. Was mit self. im Konstruktor entsteht, ist dagegen ein Instanzattribut.

5.4Bedeutung von self

Richtig: B. self ist genau das Objekt, auf dem die Methode gerade aufgerufen wird, keine Kopie und nicht die Klasse.

5.5Zweck von super().__init__(…) in der Unterklasse

Richtig: C. Es startet den Konstruktor der Oberklasse, damit deren Attribute (hier der Inhaber) auch im neuen Objekt angelegt werden.

5.6Objekt einer abstrakten Klasse erzeugen

Richtig: B. Eine Klasse mit offener @abstractmethod lässt sich nicht instanziieren, Python bricht schon beim Anlegen mit TypeError ab.

5.7(3 Punkte) Drei Ausgaben zu zwei Namen und zwei Konten, erste begründen

1. Ausgabe (½ P + ½ Begründung)
2. Ausgabe (1 P)
3. Ausgabe (1 P)

150 · 100 · False

Die Zuweisung b = a kopiert nichts: Beide Namen meinen dasselbe Konto-Objekt, die Einzahlung über den einen Namen sieht man also auch über den anderen. Das dritte Konto ist ein eigenes Objekt und bleibt bei 100. == prüft bei einer normalen Klasse (ohne @dataclass) nur, ob es dasselbe Objekt ist; gleiche Werte reichen nicht.

5.8(4 Punkte) Vier Verstöße gegen die Kapselung finden und korrigieren

ZeileKorrektur

Automatisch gibt es ½ Punkt je richtig gefundener Zeile. Die Korrektur (je ½) bewertest du selbst.

Zeile 8: Der Konstruktor schreibt auf die Property, die keinen Setter hat, also AttributeError schon beim Anlegen. Korrektur: den Startwert in self._bestand speichern.

Zeile 12: Der Getter überschreibt den Bestand bei jedem Lesen mit 0. Ein Getter soll nur lesen. Korrektur: Zeile weglassen.

Zeile 15: Der Unterstrich macht die Methode „intern“, dabei soll gerade sie von außen aufgerufen werden. Korrektur: Methode verkaufen ohne Unterstrich nennen.

Zeile 17: Auch hier wird auf die Property ohne Setter geschrieben (AttributeError). Korrektur: self._bestand verringern.

Einen Setter hinzuzufügen beseitigt zwar die Abstürze, macht den Bestand aber von außen änderbar. Das widerspricht dem Plan und bringt nur je ½ Punkt. Eine treffende Beschreibung der Stelle statt der Zeilennummer zählt in der Musterlösung voll.

5.9(5 Punkte) Fünf Lücken im Zahlungsarten-Programm ergänzen

(1) Oberklasse der Basisklasse
(2) über der Gebührenmethode
(3) Oberklasse der Kreditkarte
(4) vor .__init__
(5) aufgerufene Methode

(1) ABC · (2) @abstractmethod · (3) Zahlungsart · (4) super() · (5) gebuehr

Polymorphie: Derselbe Methodenaufruf in der Schleife landet je nach Objekt bei der Rechnung (0) oder bei der Kreditkarte (2 % von 50 = 1.00).

Zu (2): Ohne den Dekorator läuft das Programm auch, verlangt ist aber eine abstrakte Oberklasse, eine leere Lücke gibt 0 Punkte. Zu (4): Der Weg über den Klassennamen klappt nur mit zusätzlich übergebenem self und passt nicht in die Lücke; die Musterlösung gibt dafür trotzdem volle Punkte.
