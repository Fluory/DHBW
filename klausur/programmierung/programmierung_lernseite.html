1.1 Algorithmen FL

Ein Algorithmus ist eine Schrittfolge zur systematischen Lösung eines Problems (F. 10). Er beschreibt den Lösungsweg unabhängig von einer bestimmten Programmiersprache. Jeder Schritt muss so genau formuliert sein, dass eine Person oder ein Computer ihn ohne Rückfrage ausführen kann. Ein Kochrezept ist ein Alltagsbeispiel; ein Programm ist ein Algorithmus, der in einer Programmiersprache aufgeschrieben wurde.

1.1.1 Vier Anforderungen

  • Endlichkeit: Der Algorithmus endet nach endlich vielen Schritten.
  • Ausführbarkeit: Jeder Schritt lässt sich tatsächlich ausführen. „Rechnung prüfen“ allein reicht nicht, weil nicht klar ist, was genau geprüft wird.
  • Korrektheit: Er liefert das richtige Ergebnis.
  • Effizienz: Er geht sparsam mit Zeit und Speicher um.

1.1.2 Drei Eigenschaften, die man leicht verwechselt

BegriffBedeutung (F. 11)Merkhilfe
terminierendendet bei jeder erlaubten Eingabe nach endlich vielen SchrittenEr hört auf.
determiniertgleiche Eingaben und Startbedingungen liefern immer das gleiche ErgebnisEs geht um das Ergebnis.
deterministischzu jedem Zeitpunkt sind der nächste Schritt und der Zustand eindeutig festgelegtEs geht um den Weg.

Ein deterministischer Algorithmus ist immer auch determiniert: Wenn jeder Schritt feststeht, kommt bei gleicher Eingabe auch dasselbe heraus. Umgekehrt muss das nicht gelten, denn ein Algorithmus kann auf verschiedenen Wegen zum selben Ergebnis kommen.

1.1.3 Beispiel: Nachbestellung (F. 12–15)

Die Folien führen einen Algorithmus für das Lager vor. Für jeden Artikel gibt es einen Bestand, einen Meldebestand und einen Höchstbestand.

  1. Nächsten Artikel aus der Lagerliste nehmen.
  2. Ist der Bestand kleiner als der Meldebestand? Nein: weiter mit Schritt 5.
  3. Bestellmenge = Höchstbestand − Bestand.
  4. Bestellung über die Bestellmenge auslösen.
  5. Noch Artikel in der Liste? Ja: weiter mit Schritt 1. Nein: fertig.

Bei Schrauben M8 (Bestand 12, Meldebestand 20, Höchstbestand 100) wird also 100 − 12 = 88 Stück bestellt, bei Dichtringen (45, 30, 150) nichts, bei Muttern M8 (8, 25, 120) 112 Stück. Schritt 2 ist schon eine Verzweigung und Schritt 5 eine Schleife; beides kommt in VL3 als Python-Code.

1.3 Von der Maschinensprache zu Python F

1.3.1 Maschinensprache, Assembler, höhere Sprachen

Ein Prozessor führt nur Programme in binärer Form aus, die Maschinensprache. Weil sie für Menschen praktisch unlesbar ist, bekommt jeder Maschinenbefehl eine symbolische Schreibweise: den Assembler-Befehl (F. 28–29), etwa MOV (Wert laden), ADD (addieren), CMP (vergleichen) und JE (springen, falls gleich). Welche Befehle es gibt, hängt vom Prozessortyp ab. Weil Assembler hardwareabhängig und mühsam ist, entstanden ab den 1950er-Jahren höhere Programmiersprachen, die von der Hardware abstrahieren (F. 30). Früher teilte man sie in Generationen ein: 1G Maschinensprache, 2G Assembler, 3G prozedural (Fortran, Cobol, C), 3G+ objektorientiert (C++), 4G deklarativ (LISP, Prolog) (F. 31).

1.3.2 Paradigmen

Heute denkt man in Paradigmen, die nebeneinander bestehen (F. 32): imperativ/prozedural (Schritt für Schritt, C), objektorientiert (Objekte mit Daten und Methoden, Java), funktional (Funktionen ohne Seiteneffekte, Haskell) und deklarativ/logisch (was erreicht werden soll, SQL). Python ist multiparadigmatisch, vereint also mehrere Ansätze. Produktiver wird man heute vor allem durch Bibliotheken, Paketverwaltung, Versionsverwaltung und automatische Prüfwerkzeuge (F. 33).

1.4.2 Mischformen

Die Grenzen verschwimmen (F. 43–44). Viele VMs übersetzen häufig genutzten („heißen“) Code zur Laufzeit in Maschinencode; das heißt JIT (Just-in-Time). Für Python gilt (F. 45): Das Programm CPython, der Standard-Interpreter, enthält Übersetzer und VM. Es übersetzt hallo.py in Bytecode und führt ihn in der Python-VM aus. Seit Python 3.13 gibt es zusätzlich einen experimentellen JIT-Compiler. Für dich ist das ein einziger Schritt.

Typischer Fehler: „Python ist eine reine Interpretersprache.“ Laut Folien ist Python ein Beispiel für Variante 3 (Zwischencode): Quellcode → Bytecode → Python-VM.

1.6 Python F

Python wurde ab 1989 von Guido van Rossum am CWI in Amsterdam entwickelt und 1991 veröffentlicht; der Name stammt von der Comedy-Gruppe Monty Python (F. 54). Python 3 erschien 2008 und ist bewusst nicht kompatibel zu Python 2, das seit 2020 nicht mehr gepflegt wird. Jedes Jahr im Oktober erscheint eine neue Version; im Kurs nutzen wir Python 3.14.

Zentrale Eigenschaften (F. 56):

  • multiparadigmatisch: einfache Skripte ohne Klassen, bei Bedarf voll objektorientiert
  • plattformunabhängig: Derselbe Quellcode läuft überall, wo ein Python-Interpreter installiert ist.
  • dynamisch, aber stark typisiert: Jeder Wert hat einen festen Typ, Variablen haben keinen (genauer in VL2).
  • automatische Speicherverwaltung: Nicht mehr benötigte Objekte werden selbst freigegeben.
  • „Batteries included“: große Standardbibliothek und Hunderttausende Pakete im Python Package Index (PyPI)

Weil Python Datentypen erst beim Ausführen prüft, schreiben wir im Kurs von Anfang an Typangaben dazu und lassen ein Prüfwerkzeug darüber laufen (F. 55).

1.8 Das erste Programm FL

1.8.1 Aufbau und Syntaxmerkmale

# Unser erstes Programm
print("Hello World!")
Hello World!

print(...) gibt Text aus, Text steht in Anführungszeichen, # leitet einen Kommentar ein (F. 68). Anders als in Java brauchst du keine Klasse und keine main-Methode: Python führt die Datei von oben nach unten aus. Die wichtigsten Syntaxregeln (F. 69):

  • Einrückung bildet Blöcke, statt geschweifter Klammern wie in Java. Standard sind 4 Leerzeichen.
  • Ein Doppelpunkt leitet einen Block ein.
  • Kein Semikolon: eine Zeile, eine Anweisung.
  • Groß- und Kleinschreibung zählt: Print ist nicht print.

1.1 · Algorithmus aufschreiben (1.1) · Folie 25, Lösung L

Beschreibe in nummerierten Schritten, wie eine eingehende Lieferantenrechnung geprüft wird, bevor sie bezahlt wird. Bestellung und Lieferschein liegen vor. Welcher Schritt fängt den Fall „Rechnung über 50 Stück, geliefert wurden 40“ ab?

Lösung

So steht es in der Musterlösung:

  1. Bestellnummer auf der Rechnung ablesen.
  2. Bestellung und Lieferschein heraussuchen. Fehlt eines davon: Rechnung an den Einkauf zurückgeben, weiter mit 7.
  3. Für jede Rechnungsposition die Menge mit dem Lieferschein vergleichen.
  4. Für jede Rechnungsposition den Preis mit der Bestellung vergleichen.
  5. Gesamtbetrag nachrechnen.
  6. Stimmen Menge, Preis und Gesamtbetrag: zur Zahlung freigeben. Sonst Abweichung notieren und an den Einkauf zurückgeben.
  7. Fertig.

Schritt 3 findet die Abweichung, Schritt 6 gibt die Rechnung zurück. Typische Lücken sind ein nicht ausführbarer Schritt wie „Rechnung prüfen“, ein fehlender Fall für Abweichungen (dann endet der Algorithmus nicht sauber) und „kleine Abweichungen ignorieren“ ohne genaue Grenze.

1.3 · Begriffe in eigenen Worten (1.1.2)

Erkläre den Unterschied zwischen determiniert und deterministisch in je einem Satz.

Lösung

Determiniert: Bei gleicher Eingabe kommt immer dasselbe Ergebnis heraus. Deterministisch: Zu jedem Zeitpunkt ist eindeutig festgelegt, welcher Schritt als nächstes kommt. Das Erste betrifft das Ergebnis, das Zweite den Weg dorthin.

Lösung

2.1 Kommentare und Docstrings FQ

Ein Kommentar ist Text, den Python ignoriert; er richtet sich an Menschen. In Python beginnt er mit # und reicht bis zum Zeilenende. Für mehrere Zeilen beginnt jede Zeile mit #; einen Block-Kommentar wie /* … */ aus Java gibt es nicht (F. 8). Ein guter Kommentar erklärt, warum der Code etwas tut. Was er tut, zeigt der Code selbst (F. 9):

2.3 Variablen und Konstanten FQ

2.3.1 Ein Name zeigt auf einen Wert

Eine Variable ist in Python ein Name, der auf einen Wert zeigt, wie ein Namensschild, nicht wie eine Kiste. Sie entsteht bei der ersten Zuweisung; eine Deklaration wie int zahl; gibt es nicht (F. 31). Das = heißt „zeigt ab jetzt auf“, nicht „ist gleich“. Bei zahl = zahl + 1 rechnet Python zuerst die rechte Seite aus und lässt den Namen dann auf das Ergebnis zeigen; den alten Wert gibt Python selbst frei (F. 32). Der Typ gehört zum Wert, nicht zum Namen: Nach x = 5 darf x = "fünf" folgen (F. 34).

2.4.3 Vergleiche und logische Operatoren

Vergleiche (== != < > <= >=) liefern immer ein bool (F. 59). == vergleicht den Inhalt, auch bei Strings; ein .equals() wie in Java braucht man nicht. is fragt dagegen „dasselbe Objekt im Speicher?“ und wird vorerst nur für None benutzt: if telefon is None: (F. 60).   • = (Zuweisung) und == (Vergleich) verwechseln.
  • alter == "30" ist False, weil die Zahl 30 nicht der Text "30" ist.

3.3 match, bedingter Ausdruck und Wahrheitswerte FQL

3.3.1 match

Seit Python 3.10 vergleicht match einen Wert der Reihe nach mit festen Fällen, das Gegenstück zu switch in Java (F. 29). Der erste passende Fall wird ausgeführt, danach ist match fertig. Ein break ist nicht nötig, und ein „Durchfallen“ in den nächsten Fall gibt es nicht. case _: passt immer, wie default, und ist optional. Mehrere Werte verbindest du mit | (F. 31):

        case "A" | "B" | "C":
            print(note, "Bestanden")
        case "D" | "E" | "F":
            print(note, "Nicht bestanden")
        case _:
            print(note, "Ungültige Eingabe")

3.4 Logische Operatoren in Bedingungen FQL

3.4.1 Rangfolge

Python wertet zuerst die Vergleiche aus, dann not, dann and und zuletzt or; Klammern kommen vor allem anderen (F. 43). Beispiel: Rabatt bekommen Studierende und Personen ab 65, beide nur mit Ausweis. Ohne Klammern liest Python ist_student or (alter >= 65 and hat_ausweis), und die Studentin ohne Ausweis bekommt den Rabatt. Setze deshalb Klammern, sobald and und or zusammen vorkommen.

3.4.2 Eine Bedingung umkehren

Entweder kehrst du die ganze Bedingung mit not ( … ) um, oder du schreibst sie um: Dann wird jede Teilbedingung umgekehrt, und aus or wird and (und umgekehrt) (F. 44). Das Gegenteil von bestellwert >= 50 or ist_premium ist bestellwert < 50 and not ist_premium. Das Gegenteil von >= 50 ist < 50, nicht <= 50.

>>> ist_student = True
>>> alter = 22
>>> hat_ausweis = False
>>> ist_student or alter >= 65 and hat_ausweis
True
>>> (ist_student or alter >= 65) and hat_ausweis
False
>>> bestellwert = 35.0
>>> ist_premium = False
>>> not (bestellwert >= 50 or ist_premium)
True
>>> bestellwert < 50 and not ist_premium
True
>>> True != False
True

Die letzte Zeile zeigt das „entweder oder“ (XOR) bei Wahrheitswerten: a != b.

Python wertet von links nach rechts aus und hört auf, sobald das Ergebnis feststeht. Ist bei and die linke Seite falsch, wird die rechte gar nicht mehr ausgewertet (F. 45). Die Absicherung gehört deshalb nach vorn:

3.6.1 Für jedes Element

Die for-Schleife geht eine Folge von Werten durch und führt den Block für jeden Wert einmal aus. Es gibt keinen Startwert, keine Bedingung und kein i++ wie in Java (F. 69). 3.6.2 Off-by-one

Ein häufiger Denkfehler: Die Schleife läuft einmal zu oft oder zu selten (F. 78). range(1, 5) liefert nur 1 bis 4; für 1 bis 5 brauchst du range(1, 6). Bei while fragst du dich: Soll die Grenze dabei sein (<=) oder nicht (<)?

break verlässt die Schleife sofort, egal ob noch Durchläufe übrig sind. continue überspringt nur den Rest des aktuellen Durchlaufs (F. 79–80). Faustregel (F. 84): break, wenn ein gesuchter Wert gefunden ist oder das Ergebnis feststeht; continue, wenn bestimmte Werte übersprungen werden sollen.

Typische Fehler bei Schleifen

  • range(1, 5) für „1 bis 5“ halten. Das Ende gehört nie dazu.
  • Im while-Block vergessen, die Zählvariable zu ändern. Ergebnis: Endlosschleife.
  • Eine Summe mit 1 oder ein Produkt mit 0 starten.
  • break und continue verwechseln: break beendet alles, continue nur diesen Durchlauf.
  • Den Doppelpunkt nach for oder while vergessen.

4.6 Rekursion FQL

4.6.1 Zwei Pflichtteile

Rekursion bedeutet, dass eine Funktion sich selbst aufruft, um ein kleineres Teilproblem derselben Art zu lösen, bis ein einfacher Fall erreicht ist (F. 62). Jede rekursive Funktion besteht aus zwei Teilen (F. 63):

  1. Abbruchbedingung (Basisfall): Wann hört sie auf? Ohne sie ruft sie sich endlos auf.
  2. Rekursiver Aufruf mit einem vereinfachten Argument, das sich der Abbruchbedingung nähert.
def fakultaet(n: int) -> int:
    """Berechnet n! rekursiv."""
    if n == 0:  # Abbruchbedingung
        return 1
    else:
        return n * fakultaet(n - 1)  # rekursiver Aufruf


def countdown(n: int) -> None:
    if n == 0:
        print("Start!")
    else:
        print(n)
        countdown(n - 1)

4.6.2 Was im Speicher passiert

Jeder Aufruf bekommt einen eigenen Rahmen mit einem eigenen n auf dem Aufrufstapel (F. 67–71).   • Definition ist kein Aufruf: def allein führt nichts aus, main ohne Klammern auch nicht.

  • Liste als Standardwert wird zwischen Aufrufen geteilt; None nehmen (ruff B006).
  • „Überladen“ mit zweitem def ersetzt die erste Funktion.

Die Musterlösung erwähnt das, auf den Folien steht es nicht. Das global ist hier nur zum Zählen da; vermeide es sonst.

import functools

aufrufe = 0


def fibonacci(n: int) -> int:
    global aufrufe  # nur zum Zählen, sonst vermeiden
    aufrufe += 1
    if n < 2:
        return n
    return fibonacci(n - 1) + fibonacci(n - 2)


@functools.cache
def fibonacci_cache(n: int) -> int:
    if n < 2:
        return n
    return fibonacci_cache(n - 1) + fibonacci_cache(n - 2)


print(fibonacci(25), aufrufe, "Aufrufe")
print(fibonacci_cache(25), fibonacci_cache.cache_info().misses, "echte Berechnungen")

def zaehle_zeichen(text: str, zeichen: str) -> int:
    if text == "":
        return 0
    treffer = 1 if text[0] == zeichen else 0
    return treffer + zaehle_zeichen(text[1:], zeichen)


def maximum(zahlen: list[int], index: int = 0) -> int:
    if index == len(zahlen) - 1:
        return zahlen[index]
    rest = maximum(zahlen, index + 1)
    return zahlen[index] if zahlen[index] > rest else rest


def potenz(basis: float, exponent: int) -> float:
    if exponent == 0:
        return 1.0
    if exponent < 0:

    return basis * potenz(basis, exponent - 1)


def fibonacci(n: int) -> int:
    if n < 2:
        return n
    return fibonacci(n - 1) + fibonacci(n - 2)

5.1 Klassen und Objekte FQL

5.1.1 Die Grundbegriffe

Objektorientierte Programmierung (OOP) ist ein Ansatz, bei dem Programme aus Objekten bestehen, die zusammenarbeiten (F. 6). Ein Objekt

  • hat Attribute: Daten, die seinen Zustand beschreiben, beim Konto etwa inhaber und kontostand;
  • hat Methoden: Funktionen, die sein Verhalten beschreiben und den Zustand ändern können, etwa einzahlen() und abheben();
  • gehört zu einer Klasse. Die Klasse ist der Bauplan, nach dem Objekte gebaut werden. Ein Objekt heißt auch Instanz der Klasse.

Aus einer Klasse lassen sich beliebig viele Objekte erzeugen. Jedes Objekt hat eigene Werte für die Attribute; die Methoden stehen nur einmal in der Klasse und gelten für alle Objekte (F. 8). Dargestellt wird eine Klasse als UML-Klassendiagramm: oben der Name, in der Mitte die Attribute, unten die Methoden (F. 7).

5.1.3 Der Konstruktor __init__ und self

__init__ läuft automatisch, wenn ein Objekt erzeugt wird. Diese Methode heißt Konstruktor und setzt den Anfangszustand (F. 15). Ihr erster Parameter self ist das neue Objekt; Python übergibt es selbst, beim Aufruf schreibst du nur Konto("Anna", 100). self.inhaber = inhaber legt das Attribut im Objekt an: links das Attribut, rechts der Parameter, beide dürfen gleich heißen.

Was bei anna = Konto("Anna", 100) passiert (F. 16–19):

  1. Python legt ein neues, noch leeres Konto-Objekt an und ruft damit __init__ auf. self zeigt auf das neue Objekt.
  2. self.inhaber = inhaber legt das erste Attribut an.
  3. self.kontostand = kontostand legt das zweite an. __init__ gibt nichts zurück, ihr Rückgabetyp ist None.
  4. Der Rahmen von __init__ verschwindet mit self, inhaber und kontostand. Das Objekt bleibt, der Aufruf liefert es, und anna zeigt darauf.

Anders als in Java werden Attribute nicht vorab im Klassenrumpf deklariert. Sie entstehen in __init__, und ihr Typ ergibt sich aus dem annotierten Parameter.

Typische Fehler bei Klassen

  • self in der Parameterliste vergessen (TypeError, ein Argument zu viel) oder vor dem Attribut vergessen (UnboundLocalError).
  • new Konto("Anna", 100) schreiben. Das gibt es in Python nicht; Konto.__init__("Anna", 100) erzeugt auch kein Objekt.
  • Zwei __init__ schreiben. Das zweite ersetzt das erste; Varianten gehen nur über Standardwerte.
  • Glauben, konto2 = konto1 sei eine Kopie. Es ist dasselbe Objekt unter zwei Namen.
  • Erwarten, dass zwei Objekte mit gleichen Werten == sind. Ohne __eq__ vergleicht == die Identität.
  • Klassenattribut über self oder ein Objekt ändern. Immer Klasse.attribut += 1.
  • Ein Attribut außerhalb von __init__ neu erfinden oder falsch schreiben. Python meldet nichts, nur ty.
  • In __str__ mit print ausgeben statt einen String mit return zurückzugeben.

Ausblick: Gleichheit mit __eq__

Dass == bei eigenen Klassen nur die Identität prüft, liegt daran, dass die Klasse keine Methode __eq__ hat. Schreibst du sie selbst, entscheidest du, wann zwei Objekte gleich sind. class Punkt:
    def __init__(self, x: int, y: int) -> None:
        self.x = x
        self.y = y

    def __eq__(self, other: object) -> bool:
        if not isinstance(other, Punkt):
            return NotImplemented
        return self.x == other.x and self.y == other.y

Methoden rufen Methoden auf

Eine Methode darf über self andere Methoden desselben Objekts aufrufen und über einen Parameter Methoden eines anderen Objekts. So bleibt die Regel „genug Geld da?“ an einer Stelle in abheben, und ueberweisen nutzt sie mit.

class Konto:
    def __init__(self, inhaber: str, kontostand: int = 0) -> None:
        self.inhaber = inhaber
        self.kontostand = kontostand

    def einzahlen(self, betrag: int) -> None:
        self.kontostand += betrag

    def abheben(self, betrag: int) -> bool:
        if betrag > self.kontostand:
            print("Abgelehnt: Der Kontostand reicht nicht.")
            return False
        self.kontostand -= betrag
        return True

    def ueberweisen(self, ziel: "Konto", betrag: int) -> bool:
        if not self.abheben(betrag):  # Methode desselben Objekts
            return False
        ziel.einzahlen(betrag)  # Methode eines anderen Objekts
        return True

        self.preis = preis
        self.bestand = bestand

    def lagerwert(self) -> Decimal:
        return self.preis * self.bestand

    def einlagern(self, menge: int) -> None:
        if menge <= 0:

Lösung

So steht es in der Musterlösung:

  1. Bestellnummer auf der Rechnung ablesen.
  2. Bestellung und Lieferschein heraussuchen. Fehlt eines davon: Rechnung an den Einkauf zurückgeben, weiter mit 7.

4.6 · Rekursiv schreiben (4.6) · Folie 82–85, Lösung L

Lösung
def zaehle_zeichen(text: str, zeichen: str) -> int:
    if text == "":
        return 0
    treffer = 1 if text[0] == zeichen else 0
    return treffer + zaehle_zeichen(text[1:], zeichen)


def maximum(zahlen: list[int], index: int = 0) -> int:
    if index == len(zahlen) - 1:
        return zahlen[index]
    rest = maximum(zahlen, index + 1)
    return zahlen[index] if zahlen[index] > rest else rest


def potenz(basis: float, exponent: int) -> float:
    if exponent == 0:
        return 1.0
    if exponent < 0:
        return 1 / potenz(basis, -exponent)
    return basis * potenz(basis, exponent - 1)


def fibonacci(n: int) -> int:
    if n < 2:
        return n
    return fibonacci(n - 1) + fibonacci(n - 2)

print(maximum([3, 8, 1]), maximum([-5, -2, -9]), maximum([3]))

4.8 · Mini-Taschenrechner (4.1, 4.2) · Folie 51, Lösung L

Lösung
def berechne(a: int, b: int, operation: str) -> float | None:
    match operation:
        case "+":
            return a + b
        case "-":
            return a - b
        case "*":
            return a * b
        case "/":
            return a / b
        case "max":
            return a if a > b else b
        case "avg":
            return (a + b) / 2
        case _:
            return None

Teste: 5 verkaufen, 100 verkaufen, 10 einlagern, dann Produkt und Lagerwert ausgeben.

Lösung
from decimal import Decimal


class Produkt:
    def __init__(self, name: str, preis: Decimal, bestand: int) -> None:
        self.name = name
        self.preis = preis
        self.bestand = bestand

    def lagerwert(self) -> Decimal:
        return self.preis * self.bestand

    def einlagern(self, menge: int) -> None:
        if menge <= 0:
            print("Die Menge muss positiv sein.")
            return
        self.bestand += menge

    def verkaufen(self, menge: int) -> bool:
        if menge > self.bestand:
            print(f"Nicht genug {self.name} auf Lager (Bestand {self.bestand}).")
            return False
        self.bestand -= menge
        return True

    def __str__(self) -> str:
        return f"{self.name}: {self.preis} Euro, Bestand {self.bestand}"

    def __repr__(self) -> str:
        return f"Produkt({self.name!r}, Decimal({str(self.preis)!r}), {self.bestand})"


def main() -> None:
    kaffee = Produkt("Kaffee 1 kg", Decimal("12.99"), 40)

    print(kaffee.verkaufen(100))

    kaffee.einlagern(-3)
    print(kaffee)

    print([kaffee, Produkt("Grüner Tee", Decimal("3.49"), 120)])
