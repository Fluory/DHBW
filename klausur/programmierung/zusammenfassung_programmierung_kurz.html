2Verzweigung: if / elif / else

Bild: Eine Weiche am Gleis: Python prüft die Bedingungen von oben nach unten und fährt in den ersten Zweig, der wahr ist. Alle anderen werden übersprungen.

punkte = 72

Fallen

  • Doppelpunkt am Zeilenende vergessen → SyntaxError. Block nicht eingerückt → IndentationError.
  • = weist zu, == vergleicht.

6Funktionen

Bild: Eine Funktion ist eine Kaffeemaschine: Du gibst etwas hinein (Parameter), sie arbeitet, und mit return kommt ein Ergebnis in deine Tasse. print dagegen zeigt nur etwas auf dem Display, in der Tasse landet nichts (None).

    return netto * (1 + satz)

7Rekursion

Bild: Matroschka-Puppen: Jede Puppe öffnet die nächstkleinere, bis die kleinste (der Basisfall) nicht mehr aufgeht. Dann wird von innen nach außen wieder zugemacht. Eine rekursive Funktion ruft sich selbst mit einem kleineren Problem auf.

def fakultaet(n: int) -> int:
    if n <= 1:                    # Basisfall
        return 1
    return n * fakultaet(n - 1)   # kleineres Problem

print(fakultaet(3))
print(fakultaet(5))
6
120
Fallen
  • Basisfall fehlt oder wird nie erreicht (z. B. fakultaet(n) statt n - 1) → RecursionError.
  • Basisfall zuerst prüfen, erst dann rekursiv aufrufen.

Aufruf-Treppe für fakultaet(3):

fakultaet(3) = 3 * fakultaet(2) ↓ wartet fakultaet(2) = 2 * fakultaet(1) ↓ wartet fakultaet(1) = 1 Basisfall! fakultaet(2) = 2 * 1 = 2 ↑ rechnet fakultaet(3) = 3 * 2 = 6 ↑ Ergebnis 6

Hinunter: jeder Aufruf wartet auf den nächsten (jeder hat sein eigenes n). Hinauf: erst jetzt wird multipliziert.

8Klassen und Objekte

Bild: Eine Klasse ist die Ausstechform, die Objekte sind die Plätzchen. Jedes Plätzchen hat eigene Werte (Attribute) und kann etwas tun (Methoden). self heißt „dieses eine Plätzchen hier“.

class Konto:
    anzahl = 0                       # Klassenattribut

    def __init__(self, inhaber: str, stand: int = 0) -> None:
        self.inhaber = inhaber       # Objektattribut
        self._stand = stand
        Konto.anzahl += 1

    @property
    def stand(self) -> int:          # lesen ohne ()
        return self._stand

    def einzahlen(self, betrag: int) -> None:
        self._stand += betrag

  • Property: a.stand sieht aus wie ein Attribut, ruft aber eine Methode auf. Ohne Setter ist es nur lesbar (letzte Zeile: AttributeError).

9Vererbung

Bild: Ein Sparkonto ist ein Konto, nur mit Zins dazu. Die Unterklasse erbt alles von der Oberklasse und darf Einzelnes überschreiben, so wie ein Kind die Rezepte der Eltern übernimmt und eines davon nachwürzt.

from typing import override

class Konto:
    def __init__(self, inhaber: str) -> None:
        self.inhaber = inhaber

    def __str__(self) -> str:
        return f"Konto von {self.inhaber}"

class Sparkonto(Konto):                  # Sparkonto IST EIN Konto
    def __init__(self, inhaber: str, zins: int) -> None:
        super().__init__(inhaber)        # Oberklasse zuerst!
        self.zins = zins

    @override
    def __str__(self) -> str:            # ueberschreiben + ergaenzen
        return f"{super().__str__()} ({self.zins} %)"

s = Sparkonto("Anna", 2)
print(s)
print(isinstance(s, Konto), isinstance(Konto("Ben"), Sparkonto))
Konto von Anna (2 %)
True False
  • class Sparkonto(Konto): in Klammern steht die Oberklasse.
  • super().__init__(inhaber) lässt zuerst die Oberklasse ihre Attribute anlegen.
  • Überschreiben: gleiche Methode, gleicher Name, in der Unterklasse. super().__str__() holt die alte Version dazu. @override (aus typing) markiert das, ty meldet dann Tippfehler im Namen.
  • isinstance(s, Konto) → True: ein Sparkonto zählt auch als Konto. Umgekehrt nicht.
Fallen
  • super().__init__(...) vergessen → AttributeError: … has no attribute 'inhaber'.
  • super.__init__ ohne Klammern hinter super → TypeError.

10Polymorphie und abstrakte Klassen

Bild: An der Kasse sagst du immer nur „Bezahlen bitte“. Ob dann Karte oder Rechnung läuft, entscheidet das Objekt, nicht du. Das ist Polymorphie. Die abstrakte Klasse ist das Formular mit Pflichtfeld: Jede Zahlungsart muss bezahlen ausfüllen, das leere Formular selbst kann man nicht benutzen.

from abc import ABC, abstractmethod

class Zahlungsart(ABC):
    @abstractmethod
    def bezahlen(self, betrag: float) -> str: ...

class Kreditkarte(Zahlungsart):
    def bezahlen(self, betrag: float) -> str:
        return f"{betrag} Euro per Karte"

class Rechnung(Zahlungsart):
    def bezahlen(self, betrag: float) -> str:
        return f"{betrag} Euro auf Rechnung"

for art in [Kreditkarte(), Rechnung()]:   # gleicher Aufruf,
    print(art.bezahlen(9.5))               # anderes Verhalten
Zahlungsart()
9.5 Euro per Karte
9.5 Euro auf Rechnung
TypeError: Can't instantiate abstract class Zahlungsart without an implementation for abstract method 'bezahlen'
  • Abstrakt braucht zwei Zutaten: erben von ABC und @abstractmethod über der Pflichtmethode. Import: from abc import ABC, abstractmethod.
  • Die Schleife ruft überall dasselbe art.bezahlen(...) auf. Welche Version läuft, hängt vom Objekt ab.
  • Neue Zahlungsart = neue Unterklasse. Der Code mit der Schleife bleibt gleich.
Fallen
  • Abstrakte Klasse erzeugen oder Pflichtmethode in der Unterklasse vergessen → TypeError: Can't instantiate abstract class …
  • @abstractmethod ohne (ABC) → kein Fehler, nichts wird geprüft.

11Projekt Kaffeeshop in 5 Zeilen

Bild: Das Lager ist ein Regal voller Produkte. Im Warenkorb liegen keine Produkte, sondern Zettel („3 × French Press“). Das sind die Positionen.

Bausteinin einem Satz
Lagerhat eine Liste von Produkten (hat ein, keine Vererbung).
Warenkorbhat eine Liste von Positionen, am Anfang leer: self.positionen = [].
Positionein Zettel aus Produkt und Menge (@dataclass).
finden(nummer)Schleife über die Produkte. Treffer → sofort return produkt. Erst nach der Schleife return None.
hinzufuegen(p, menge)Menge im Korb + neue Menge > Bestand → False. Liegt das Produkt schon im Korb, wird die Menge auf dem Zettel erhöht, sonst kommt ein neuer Zettel dazu → True.
from dataclasses import dataclass

@dataclass
class Produkt:
    nummer: int
    name: str
    bestand: int

@dataclass
class Position:                      # ein Zettel: Produkt + Menge
    produkt: Produkt
    menge: int

class Lager:
    def __init__(self, produkte: list[Produkt]) -> None:
        self.produkte = produkte

    def finden(self, nummer: int) -> Produkt | None:
        for produkt in self.produkte:
            if produkt.nummer == nummer:
                return produkt       # gefunden: sofort raus
        return None                  # erst NACH der Schleife

class Warenkorb:
    def __init__(self) -> None:
        self.positionen: list[Position] = []

    def hinzufuegen(self, produkt: Produkt, menge: int) -> bool:
        for pos in self.positionen:
            if pos.produkt.nummer == produkt.nummer:
                if pos.menge + menge > produkt.bestand:
                    return False
                pos.menge += menge   # vorhandenen Zettel erhoehen
                return True
        if menge > produkt.bestand:
            return False
        self.positionen.append(Position(produkt, menge))
        return True

lager = Lager([Produkt(101, "Kaffee", 40), Produkt(203, "French Press", 3)])
korb = Warenkorb()
fp = lager.finden(203)
print(fp)
print(lager.finden(999))
if fp is not None:
    print(korb.hinzufuegen(fp, 3), korb.hinzufuegen(fp, 1))
print(len(korb.positionen), korb.positionen[0].menge)
Produkt(nummer=203, name='French Press', bestand=3)
None
True False
1 3

Was passiert unten? finden(203) trifft in Runde 2. finden(999) trifft nie, also None. 3 French Press passen genau (3 ≤ 3), die vierte nicht mehr (3 + 1 > 3). Ergebnis: eine Position mit Menge 3.

Fallen
  • else: return None direkt unter dem if in finden() → die Suche endet nach Runde 1, 203 wird nie gefunden.
  • Ergebnis von finden() nicht auf None prüfen → AttributeError: 'NoneType' object has no attribute …
  • Bei der Bestandsprüfung die Menge im Korb vergessen → 4 von 3 im Korb.
  • Immer append, statt die Menge zu erhöhen → dasselbe Produkt steht zweimal im Korb.
  • Methoden liefern True/False mit return. Die Meldungen für den Nutzer druckt main.py.
