VL1Einführung: Algorithmen, Übersetzung, Python

1.1 Algorithmen

Ein Algorithmus ist eine Schrittfolge, die ein Problem systematisch löst. Er beschreibt den Lösungsweg unabhängig von der Programmiersprache. Jeder Schritt ist so genau beschrieben, dass eine Person oder ein Computer ihn ohne Rückfrage ausführen kann. An einen Algorithmus stellt man vier Anforderungen: Endlichkeit (er endet), Ausführbarkeit, Korrektheit und Effizienz (er geht sparsam mit Zeit und Speicher um).

EigenschaftBedeutungMerkhilfe
terminierendendet bei jeder erlaubten Eingabe nach endlich vielen SchrittenEr hört auf.
determiniertGleiche Eingaben und Startbedingungen liefern immer das gleiche Ergebnis.Es geht um das Ergebnis.
deterministischDer nächste Schritt und der Zustand sind zu jedem Zeitpunkt eindeutig festgelegt.Es geht um den Weg.

Folienbeispiel Nachbestellung: (1) Nimm den nächsten Artikel aus der Lagerliste. (2) Ist der Bestand kleiner als der Meldebestand? Wenn nein, weiter mit 5. (3) Bestellmenge = Höchstbestand − Bestand. (4) Löse die Bestellung aus. (5) Sind noch Artikel in der Liste? Wenn ja, weiter mit 1, sonst fertig. Für die Schrauben (Bestand 12, Meldebestand 20, Höchstbestand 100) werden 100 − 12 = 88 Stück bestellt, für die Muttern (8 / 25 / 120) 112 Stück. Bei den Dichtringen (45 / 30) wird nichts bestellt. Gleiche Bestände ergeben immer dieselbe Bestellung (determiniert).

1.3 Von der Maschinensprache zu Python

Ein Prozessor versteht nur Maschinensprache, also binäre Befehle. Assembler schreibt dieselben Befehle symbolisch (MOV, ADD, CMP, JE) und hängt deshalb vom Prozessortyp ab. Ab den 1950er-Jahren kamen höhere Programmiersprachen, die von der Hardware abstrahieren. Früher teilte man die Sprachen in Generationen ein. Heute spricht man von Paradigmen, die nebeneinander bestehen: imperativ bzw. prozedural, objektorientiert, funktional, deklarativ bzw. logisch. Python ist multiparadigmatisch, du kannst darin also nach mehreren Paradigmen programmieren.

1.4 Python: Eigenschaften, Syntax, Werkzeuge

Guido van Rossum hat Python ab 1989 entwickelt und 1991 veröffentlicht, den Namen hat es von Monty Python. Python 3 erschien 2008 und ist bewusst inkompatibel zu Python 2, im Kurs wird Python 3.14 verwendet. Python ist plattformunabhängig, hat eine automatische Speicherverwaltung und eine große Standardbibliothek („Batteries included“). Außerdem ist es dynamisch, aber stark typisiert: Jeder Wert hat einen festen Typ, Variablen haben keinen. Python wandelt nicht heimlich um, deshalb gibt "5" + 1 einen Fehler (Kap. 2).

Syntaxregeln

  • Einrückung bildet Blöcke (Standard: 4 Leerzeichen), geschweifte Klammern gibt es dafür nicht.
  • Ein : leitet einen Block ein. Ein Semikolon am Zeilenende braucht man nicht.
  • Groß- und Kleinschreibung zählt: Print ist nicht print.
  • # leitet einen Kommentar ein. Erstes Programm: print("Hello World!")
  • Eine Klasse oder main ist nicht nötig, die Datei läuft von oben nach unten.

Was bei uv run hallo.py passiert

  1. CPython prüft zuerst die Syntax der ganzen Datei. Einen Tippfehler bemerkt es also, bevor eine einzige Zeile läuft.
  2. Es übersetzt den Code in Bytecode. Für importierte Module wird er in __pycache__/ gespeichert.
  3. Die Python-VM führt den Bytecode aus.

Typische Fehler und Fallen
  • „Determiniert“ (gleiches Ergebnis) und „deterministisch“ (eindeutiger nächster Schritt) werden oft verwechselt.
  • Python ist nicht „rein interpretiert“. Es übersetzt erst in Bytecode, den dann eine VM ausführt.
  • „Dynamisch typisiert“ heißt nicht „schwach typisiert“. Python rät nicht, deshalb gibt "Alter: " + 36 einen TypeError.
Das musst du können

  • Stack (LIFO) und Queue (FIFO) erklären und passend zuordnen
  • Interpreter, Compiler und Zwischencode mit Vor- und Nachteilen vergleichen und Python einordnen
  • die Syntaxregeln anwenden und sagen, wofür uv, ruff und ty zuständig sind

2.3 Variablen: Namen zeigen auf Werte

Eine Variable ist ein Name, der auf einen Wert zeigt. Stell sie dir wie ein Namensschild vor, das an einem Objekt hängt, nicht wie eine Box. Der Typ gehört zum Wert, nicht zum Namen. Eine Variable entsteht bei der ersten Zuweisung, eine Deklaration wie in Java gibt es nicht. = bedeutet „zeigt ab jetzt auf“. Bei zahl = zahl + 1 rechnet Python zuerst die rechte Seite aus und hängt dann das Schild um. Den alten Wert gibt Python automatisch frei, wenn kein Name mehr auf ihn zeigt.

alter: int = 25            # Typangabe: Versprechen an ty
breite, hoehe = 1920, 1080 # Mehrfachzuweisung
x = y = 0                  # zwei Namen, ein Wert
a, b = 1, 2
a, b = b, a                # Tauschen ohne Hilfsvariable
wert = 3,5                 # Falle: Komma statt Punkt!
print(alter, breite, hoehe, x, y, a, b)
print(wert, type(wert))

(3, 5) <class 'tuple'>

Typangaben (name: typ = wert) ignoriert Python beim Ausführen. ty prüft sie aber vorher, z. B. meldet es bei alter: int = "25" den Fehler error[invalid-assignment]. Merksatz der Folie: „Die Typangabe ist ein Versprechen. ty passt auf, dass Sie es halten.“

Tauschen mit a, b = b, a funktioniert, weil Python zuerst die ganze rechte Seite auswertet.

2.7 Syntax vs. Semantik: vier Fehler, drei Prüfer

Die Syntax ist die Grammatik, also die Form des Codes. Die Semantik ist seine Bedeutung, also was er bewirkt. Code kann syntaktisch korrekt und trotzdem semantisch falsch sein.

Einen Traceback liest du von unten nach oben:

  1. Die letzte Zeile sagt, was passiert ist: Fehlerart und Meldung.
  2. Darüber steht, wo es passiert ist: Datei und Zeile.
  3. Die Markierung ^ zeigt auf die genaue Stelle.

„Start“ wird noch ausgegeben: Bei einem Laufzeitfehler laufen die Zeilen davor, bei einem Syntaxfehler läuft gar nichts.

Typische Fehler und Fallen
  • / liefert immer float (6 / 3 → 2.0), und -7 // 2 ergibt −4.
  • 5 + 2 / 2 ergibt 6.0 und nicht 3.5, denn Punkt geht vor Strich. Das ist ein Logikfehler ohne Fehlermeldung.
  • 0.1 + 0.2 == 0.3 ergibt False, und int(19.99 * 100) ergibt 1998. Floats nie mit == auf „krumme“ Werte prüfen, für Geld Decimal("…") nehmen.
Das musst du können

  • String-Index, Slicing und f-Strings mit :.2f anwenden; die vier Fehlerarten erkennen
  • Ergebnisse von int(), str(), round() vorhersagen; Docstring (Google-Stil) und Final-Konstante schreiben

3.2 Bedingte Anweisungen: if, elif, else

Um die Bedingung stehen keine Klammern, am Ende steht ein Doppelpunkt. else steht auf derselben Einrückungsebene wie if. Bei if–else läuft genau einer der beiden Blöcke. Mit elif sparst du dir verschachtelte ifs. Python prüft die Bedingungen der Reihe nach und hört beim ersten Treffer auf, die übrigen Zweige werden dann gar nicht mehr geprüft.

temperatur = 25
if temperatur < 0:
    print("Gefriert!")
elif temperatur < 20:
    print("Kühl.")
elif temperatur < 30:
    print("Angenehm.")
else:
    print("Heiß!")
Angenehm.

Reihenfolge zählt: Bei Bereichsprüfungen sortierst du die Bedingungen von oben nach unten. Steht in der Notenaufgabe punkte >= 50 an erster Stelle, bekommt auch jemand mit 95 Punkten „ausreichend“, und zwar ohne Fehlermeldung (Logikfehler). Grenzen testest du mit einem Wert genau auf der Grenze und einem knapp darunter (90 und 89).

3.3 match und der bedingte Ausdruck

note = "E"

Nicht bestanden

match gibt es seit Python 3.10, es entspricht Javas switch. Es vergleicht einen Wert mit festen Fällen, und der erste passende Fall gewinnt. Ein break braucht man nicht, es gibt kein Durchfallen in den nächsten Fall. case _: passt immer und ist der Standardfall (Java: default). Mehrere Werte verbindest du mit |.

if–elif bleibt der Normalfall, weil nur damit Bereiche wie note < 3 geprüft werden können.

Bedingter Ausdruck (Kurzform von if–else, Java: b ? x : y): status = "offen" if betrag > 0 else "bezahlt". Er wählt einen von zwei Werten und sollte nicht verschachtelt werden. ruff schlägt ihn selbst vor, wenn ein if–else nur eine Variable setzt.

4.1 Funktionen definieren und aufrufen

Eine Funktion ist ein abgeschlossener Codeblock mit einem Namen, der eine bestimmte Aufgabe erfüllt. Sie bekommt Eingaben (Parameter), rechnet damit und liefert ein Ergebnis, ähnlich einer kleinen Maschine. Einige kennst du schon: print(), len(), int(), input(). 4.7 Rekursion

Bei einer Rekursion ruft eine Funktion sich selbst auf, um ein kleineres Teilproblem derselben Art zu lösen. Das geht so lange weiter, bis ein einfacher Fall erreicht ist. Jede rekursive Funktion hat zwei Pflichtteile:

  1. eine Abbruchbedingung (Basisfall): Sie legt fest, wann die Rekursion aufhört, und verhindert endlose Rekursion.
  2. einen rekursiven Aufruf mit einem vereinfachten Argument, das sich der Abbruchbedingung nähert.
def fakultaet(n: int) -> int:
    """Berechnet n! rekursiv."""
    if n == 0:                         # Abbruchbedingung
        return 1
    else:
        return n * fakultaet(n - 1)    # rekursiver Aufruf

def summe_bis(n: int) -> int:
    return 0 if n == 0 else n + summe_bis(n - 1)

def countdown(n: int) -> None:         # nur Aktion
    if n == 0:
        print("Start!")
    else:
        print(n, end=" ")
        countdown(n - 1)

print(fakultaet(3), fakultaet(5), summe_bis(7))
countdown(3)
6 120 28
3 2 1 Start!

Im Speicher bekommt jeder Aufruf einen eigenen Rahmen mit einem eigenen n. Beim Abstieg wartet jeder Rahmen auf das Ergebnis des nächsten. Erst der Basisfall liefert einen Wert, danach rechnen beim Aufstieg alle wartenden Rahmen ihr Ergebnis aus.

Ohne Abbruchbedingung, oder wenn sie nie erreicht wird, wächst der Stapel immer weiter. fakultaet(-1) mit if n == 0 läuft z. B. über −1, −2, … bis zum RecursionError: maximum recursion depth exceeded (Java: StackOverflowError). sys.getrecursionlimit() liefert etwa 1000 Rahmen. Python optimiert Rekursion nicht weg (keine „Tail-Call-Optimierung“), deshalb bricht auch fakultaet(5000) ab. Für große n löst man die Aufgabe iterativ, in echten Programmen mit math.factorial().

def fakultaet_iterativ(n: int) -> int:
    ergebnis = 1                 # 0! = 1! = 1
    for i in range(1, n + 1):
        ergebnis *= i
    return ergebnis

print(fakultaet_iterativ(5), fakultaet_iterativ(0))
120 1

Beispiel: fakultaet(-1) mit der Abbruchbedingung n == 0 endet in RecursionError: maximum recursion depth exceeded. Robuster wäre if n <= 0.

Was bei Konto("Anna", 100) passiert:

  1. Python legt ein neues, noch leeres Objekt an und ruft damit __init__ auf. self zeigt auf dieses neue Objekt.
  2. self.inhaber = inhaber legt das Attribut im Objekt an. Links steht das Attribut, rechts der Parameter, und beide dürfen gleich heißen.
  3. Genauso entsteht self.kontostand. __init__ gibt nichts zurück (-> None).
  4. Der Rahmen von __init__ verschwindet, das Objekt bleibt. Konto(…) liefert es zurück, und anna zeigt jetzt darauf.

ben.kontostand = 300 ändert nur das Objekt, auf das ben zeigt.

  • Ein new wie in Java gibt es nicht, du rufst einfach die Klasse auf.
  • Attribute werden nicht vorab im Klassenrumpf deklariert wie in Java. Sie entstehen in __init__, ihr Typ ergibt sich aus dem annotierten Parameter.
  • Genau ein __init__, denn Überladung gibt es nicht. Varianten baust du mit Standardwerten: Mit kontostand: int = 0 funktionieren Konto("Anna", 100) und Konto("Ben"). Ohne __init__ erzeugt Konto() ein Objekt ohne Attribute.
  • Namen mit doppelten Unterstrichen wie __init__ haben für Python eine feste Bedeutung. Man nennt sie Dunder-Methoden („double underscore“).
  • Beträge stehen auf den Folien als int in ganzen Euro, damit der Code kurz bleibt. Für Cent-Beträge nimmt man Decimal.

@dataclass ist eine Kurzform für Datenklassen. Aus den annotierten Attributen im Klassenrumpf erzeugt Python __init__, __repr__ und __eq__ automatisch. == vergleicht dann die Werte und nicht mehr die Identität. from dataclasses import dataclass
from decimal import Decimal

@dataclass
class Produkt:            # in der Lösung: normale Klasse mit Properties (Übung 4)
    name: str
    preis: Decimal
    bestand: int

@dataclass
class Position:           # eine Position HAT ein Produkt
    produkt: Produkt
    menge: int

    def summe(self) -> Decimal:
        return self.produkt.preis * self.menge

class Warenkorb:          # HAT einen Kunden und mehrere Positionen
    def __init__(self, kunde: str) -> None:
        self.kunde = kunde
        self.positionen: list[Position] = []   # leere Liste in __init__

    def hinzufuegen(self, produkt: Produkt, menge: int) -> None:
        if menge > produkt.bestand:
            print(f"Nur noch {produkt.bestand} x {produkt.name} auf Lager.")
            return
        self.positionen.append(Position(produkt, menge))

    def gesamtsumme(self) -> Decimal:
        summe = Decimal(0)
        for position in self.positionen:
            summe += position.summe()
        return summe

Geschichte: In den 1980ern stößt die prozedurale Programmierung bei großen Systemen an ihre Grenzen (wenig Modularität, schwer wartbar). Typische Fehler und Fallen
  • self in der Methodendefinition vergessen: Beim Aufruf gibt es dann einen TypeError, weil Python das Objekt trotzdem als erstes Argument übergibt. Ebenso falsch ist, self. vor einem Attribut zu vergessen (kontostand += betrag statt self.kontostand += betrag).
  • __init__ gibt nichts zurück (-> None), das Objekt liefert der Aufruf Konto(…). Ein new gibt es nicht.
  • konto2 = konto1 erzeugt kein zweites Objekt.
  • == ohne __eq__ bzw. ohne @dataclass vergleicht die Identität. Zwei Objekte mit gleichen Werten sind dann nicht gleich.
  • Ein Tippfehler bei der Attributzuweisung legt still ein neues Attribut an, nur ty findet ihn.
  • Ein Klassenattribut über ein Objekt ändern legt ein Instanzattribut an. Ändere es immer über den Klassennamen.
  • Eine Property ruft man ohne Klammern auf (lena.jahresgehalt). Ohne Setter ist sie nur lesbar (AttributeError).
  • _attribut ist nur eine Konvention, Python schützt nichts.
  • Ohne __str__ zeigt print(obj) nur <… object at 0x…>.
